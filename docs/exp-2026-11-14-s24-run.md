# 人工跑一遍：S2-4《如何防止 AI 越改越崩！》（2026-11-14）

不是产品，是「我当工具、用户当用户」跑一次真实流程（D11），只记哪一步有用、哪一步多余。

## 1. 判断（0–30 秒，一屏）
- 给的东西：视频 10 块字幕 → 压成一张四行表（哪段必看/哪段跳）。结论「6:30 里只看 1:31–3:49（git）」。
- 依据不是猜：实测本机 `git --version` → CommandNotFoundException；`bili-notes\AGENTS.md` 里已经写着「项目没有 git，装不了提交钩子」。所以后半（AGENTS.md 原理/该写什么）对用户是复习，前半才是盲区。
- 用户反应：接受，并立刻引出新想法（插件可以接用户自己的 agent，见文末）。

## 2. 任务（10 分钟，真跑）
视频给的 4:35 规矩「每完成一小功能先确认 + git 提交」被落成可执行 4 步：装 git → init + .gitignore + 首个 commit → 故意删一行弄崩 → 回滚。
实际执行（我当工具）：
- 装 git：Git for Windows **MinGit 2.56.1 便携版**（`%LOCALAPPDATA%\MinGit`，38 MB zip，无管理员、无 UAC），加进用户 PATH。
- `git init -b main`，仓库根 = `bili-notes`；`.gitignore` = `dist/` `node_modules/` `test/ocr/build/` `*.log`。跟踪 124 个文件 / 100.0 MB 原始体积 → 压缩后 21.61 MiB。
- 首个存档 `a54d106`。
- 弄崩：删掉 `src/content.js:1707` 的 `const STATE_TEXT = {` → `node --check` 报 `SyntaxError: Unexpected token ':'` @1708，exit=1。
- 回滚：`git restore src/content.js` **66 ms**，`node --check` exit=0，`git status` clean。

## 3. 反馈给视频的缺口
视频说「回滚版本全都可以让 agent 替你敲命令」，但**从头到尾没给一条具体回滚命令**（commit / restore / log 一个都没有）。用户真跑时这一步只能回头问。这正是「陪读」该补的：视频讲概念的那一格，配一条能直接粘的命令。

## 4. 用户的新想法（未做，记录）
「插件完全可以和用户自己的 agent（Codex、DSH 这些）关联起来，又能脱掉不少功能。」⇒ 如果用户本来就有能读文件、跑命令、能对话的 agent，插件不必自己攒模型调用/会话/追问，只负责「把这一屏的判断喂给它」。与 v0.8「一屏判断 + 可追问 + 回跳」不冲突，是砍实现而不是砍功能。后续再议。
