# 实测数据：B站 字幕到底有多不可靠

这个文档放原始证据，README 里只留结论。所有数字都来自真机 / 真实接口，不是估算。

## 一、同一个视频，字幕接口会返回不同文件

2026-11-13，用户自己的课 `BV1JynA6aEug`（401 秒，Git 那期），同一个 `(aid, cid)` 连取 8 次：

| 结果 | 次数 |
| --- | --- |
| 正确的 Git 字幕 | 5 |
| 电动车相关的字幕 | 1 |
| 时长超出视频的字幕 | 1 |
| HTML 错误页（不是字幕） | 1 |

正确的那份只出现 5/8 次。如果实现成「取第一个通过闸门的」，有一半概率把别的视频的笔记写给你——**这正是市面上字幕工具最常见的失效方式**。

更早的样本：194 秒的视频能返回 1606 秒的字幕；两个完全不同的街舞视频返回同一首歌的歌词。

## 二、60 条真实视频的可用率

随机抽 60 条视频，直接调字幕接口，按闸门判据分类：

| 结果 | 条数 | 按什么判 |
| --- | --- | --- |
| ok（时长覆盖 0.85~1.10） | **10** | 现在的闸门 |
| truncated（覆盖 < 0.85） | **13** | 现在的闸门 |
| overflow（覆盖 > 1.10） | **17** | 现在的闸门 |
| emptyUrl（有轨但 url 为空） | 9 | 有无文件 |
| noSubs（没有中文轨） | 11 | 有无文件 |

有字幕文件的 40 条里，真正能用的只有 **10 条（17%）**。

> 更正（2026-11-14）：这张表早期写的是 ok 14 / truncated 9，那是用 **0.35~1.15** 的宽松阈值统计的（23%）。宽阈值会把「字幕只覆盖 40% 的视频」也算 ok：`test/fixtures/probe-results.json` 里 `verdict: "ok"` 却有 4 条覆盖只有 0.40~0.47，就是这个原因。改成现在闸门的 0.85~1.10 后是 10 条（17%）。fixture 里那个 `verdict` 字段是早期探针的产物，**不要拿它当判据**；`realdata.test.mjs` 也只用 `track` 里的原始数字重算。

原始数据在 `test/fixtures/probe-results.json`（60 条，含每条的时间覆盖比），`node test/realdata.test.mjs` 拿它做回归：40 条有文件的样本 **40/40 与"时长闸期望"一致**。

覆盖率分布：`<0.6: 13` / `0.6~0.85: 0` / `0.85~1.10: 10` / `>1.10: 17`。注意 0.6~0.85 是空的——接口不返回"稍微不完整"的字幕，要么基本完整，要么差一大截，这让覆盖比成为一个很干净的判据。

## 三、闸门实际判据

| 闸门 | 判据 | 失败时界面写什么 |
| --- | --- | --- |
| 存在性 | 有中文轨且 url 非空 | 这个视频没有字幕 / 字幕轨为空 |
| 时长 | 覆盖比 = 末句时间 / 视频时长，要求 0.85~1.10 | 字幕只有一部分 / 字幕比视频还长 |
| 结构 | ≥8 行、≥120 字、平均句长≥3、累计时长比≤1.15、最大空档 ≤ max(90s, 时长×10%) | 字幕结构异常 |
| 稳定 | 最多取样 5 次，按哈希投票；同一份文件拿到 3 票提前收；票数≥2 才算 stable，只有一份通过算 single | 单次取样（未复核） |
| 登录 | 未登录直接停（接口返回 0 轨） | 请先登录 B站 |

投票打平（两种文件各 2 票）或每次都不同 ⇒ 判 `ambiguous`，**不猜**，给「再试一次」。

「两次取样一致」只说明取样稳定，**不说明内容属于这个视频**（已实测到时长对得上但内容是别的视频歌词的情况），所以界面文案不写「已验证」。

## 四、真模型跑出来的数字

deepseek-flash，真实字幕 `BV1GyZYYNErW`（2132 句 / 25311 字 / 70 分钟 → 120 块）：

- 单块 prompt 约 540~633 token，输出 250~492 token，耗时 96~184 ms。
- 6 个连续块：23 条要点活下来 22 条。
- 要点的时间戳和原文**不由模型手抄**：模型只给 `sentence_ids`，时间由字幕句的 from/to 推导，引文由这些句子的原文拼接。模型若自拟引文且与所选句子二字片段命中 <50%，整条丢弃。
- 70 分钟视频全部跑完 ≈ 6~7 万 input token，几分钱到一毛钱（按 ¥1/百万 token 的便宜模型算）。面板右上角实时显示。

## 六、画面字幕（硬字幕）兜底

有的视频字幕烧在画面里，接口返回 0 轨。v0.6.0 起可以本机 OCR 读底部字幕带：

- 1080p 硬字幕（耶鲁公开课 `BV1K5x56nEVe`，46 分钟，接口 0 轨，右下角有校徽）：100 秒出 3 条带「画面字幕（识别）」的真笔记。
- 480p 会被明确拒绝（中文字只有十几像素），提示「清晰度太低，认不出画面字幕」，不进入识别、不耗 CPU。
- 错字会进原话（读的是像素），数字、人名、公式最容易错；40 条样本里肉眼可见错字 3~5 处，不影响理解。
- OCR 引擎对比：tesseract.js（chi_sim_best）在 1080p 课件帧上基本不可用（正文被认成「在三角形 4BC 中，已知 w，D，4」），换 PP-OCRv6 tiny（ONNX Runtime Web + wasm）后同一帧几乎全对，初始化 270ms、单帧 1.3~1.5 秒，全在本机。

## 七、设置页的端点白名单（W2-1）

为什么要在保存时拦：MV3 里对**没在 `host_permissions` 声明过**的域名发 `fetch`，只会抛 `TypeError: Failed to fetch`——和断网、DNS 错、Key 错是同一句话。事后再想区分已经不可能，所以必须在用户点「保存」那一刻拦下来，并告诉他能用哪几家。

| 检查 | 行为 | 对应断言 |
| --- | --- | --- |
| 预设 6 家都在 manifest 里 | 选了预设就一定能保存 | endpoint 6 条 |
| 协议不符（只有 https 权限时填 http） | 拦 | endpoint 1 条 |
| 后缀伪装 `api.deepseek.com.evil.com` | 拦 | endpoint 1 条 |
| 前缀伪装 `evilapi.deepseek.com` | 拦 | endpoint 1 条 |
| 通配 `*.deepseek.com` | 命中裸域与子域，不吃伪装域 | endpoint 4 条 |
| 没权限的域名点保存 | 不写 storage + 报错点名域名 + 列出允许名单 | options 4 条 |
| 没权限的域名点「测试连接」 | 不发请求，同一道校验 | options 2 条 |
| 空 Key 点「测试连接」 | 先提示填 Key，不发请求 | options 2 条 |

配置：`http://localhost/*` 与 `http://127.0.0.1/*` 已在 manifest 里（本机 Ollama / vLLM），端口不影响判定。

变异测试：把 `src/options.js` 里两道 `if (!allow.ok) return show(originError(allow), true);` 删掉后重跑 `test/options.test.mjs`，6 条变红；恢复后 21 条全绿。

`node test/run-all.mjs` 现在 **613 条断言**（gate 40 / vote 10 / pages 15 / section 25 / visual 9 / hardsub 61 / pipeline 11 / endpoint 30 / options 21 / transcript 30 / batch 28 / diag 20 / chat 18 / searchindex 45 / studystate 29 / course 50 / season 17 / concepts 34 / study 35 / studyplan 45 / realdata 40）。
## 八、没配 API Key 也能拿到字幕全文（W2-3）

为什么要有这条：闸门跑完的那一刻，字幕已经在手里了，但以前只有模型返回之后才有「笔记」，所以没填 Key 的用户点「导出」得到的是一份只有标题和 BV 号的空文件——看起来像产品坏了。

现在的行为：点「导出」时如果还没有任何 AI 笔记，导出的是**字幕全文**。

| 检查 | 行为 | 对应断言 |
| --- | --- | --- |
| frontmatter | `notes: transcript-only`、`source`、`subtitle_source`、`verified` 都写上 | transcript 4 条 |
| 逐句 | 每句一行 `- [mm:ss](可点链接) 原句` | transcript 2 条 |
| 时间格式 | 61.4 秒 → `01:01`；3725 秒 → `62:05`（分钟不封顶，不写成 `01:02:05`） | transcript 2 条 |
| 多 P | 写 `page: 2/5` 与 `part`，标题带「（P2/5 · 下半场）」 | transcript 2 条 |
| 句内换行 | 压成一行，避免 Markdown 列表断成半句 | transcript 1 条 |
| 画面字幕来源 | 额外写 `subtitle_note: 画面字幕识别，可能有错字` | transcript 2 条 |
| 空字幕 | 不崩，正文写清「可能未登录 / 作者没开 AI 字幕 / 接口没返回」 | transcript 2 条 |
| 缺参数 | `sentences` 为 null 不抛异常；没有跳转函数时退化成 `#t=5` | transcript 2 条 |

状态条文案也改了：队列因为 `no-key` 停下时，不再说「模型调用失败」，而是「还没填 API Key：现在点「导出」能拿到字幕全文（N 句，带时间戳）；想变成带引文的结论就点「设置」填一个」。

真浏览器验证（2026-11-14，预览页 + 假数据）：起 `node test/preview-server.mjs 8799`，在浏览器里打开 `/video/BV1TESTPREVIEW`（假 chrome API + 60 句假字幕），把 `window.__bnState.notes` 清空后点面板上的「导出」——浏览器真的下载了 `光合作用 · 假数据预览.md`：6,671 字节 / 77 行 / 60 条 `- [mm:ss](链接) 原句` / frontmatter 里 `notes: transcript-only`。这证明「没有 AI 笔记 → 导出字幕全文」的分支在真实 DOM 里确实被走到。
真扩展验证（2026-11-14，真 Edge 157 加载仓库根，真 B站 页面 https://www.bilibili.com/video/BV1twZ4YzEmv）：在内容脚本自己的执行上下文里调用 `window.__bnTranscriptMarkdown()`，拿到 **99,951 字节 / 1,407 行 / 1,390 条** `- [mm:ss](链接) 原句`，frontmatter 是 `source` / `title: 深度|| 香火之战，车迟国的教皇实验` / `subtitle_source: ai-zh` / `verified: single-sample` / `notes: transcript-only` / `exported`。也就是说分母不是空壳（旧行为下这里只有标题和 BV 号）。
真扩展里点按钮落盘也验了（2026-11-14，CDP `Browser.setDownloadBehavior` + 真点 `#btnExport`）：真 Edge 里真的下载了 `我的世界克苏鲁全集：一口气看完.md`，**168,723 字节**，frontmatter 是 `verified: two-samples-agree` / `visual_frames: 6`，正文是带引文和时间戳的 AI 笔记（这个视频已经整理过，所以走的是笔记分支）。
## 九、出错时的一键诊断（W2-4）

为什么要有：陌生人报「字幕拿不到」时，来回问「哪个视频 / 什么判定 / 什么端点」要花三四轮，很多人问一轮就走了。所以状态条不是绿色（warn 或 bad）时，面板会多出一个「复制诊断」，点一下拿到：

| 内容 | 例子 | 为什么需要 |
| --- | --- | --- |
| 版本 | `bili-notes 0.7.3` | 老版本的问题可能已经修了 |
| 页面 | `https://www.bilibili.com/video/BV1xx411c7mD?p=2（P2/5）` | 复现必须有 BV 号；推广参数（`spm_id_from`、`vd_source`）会被去掉 |
| 字幕判定 | `stable · 4 次取样一致 · ai-zh · 412 句` | 区分「拿不到」和「拿到了但不对」 |
| 端点 | `api.deepseek.com · 模型 deepseek-chat · Key 已填` | 只写域名与「填没填」，**不写 Key 内容** |
| 本机 OCR | `可用` / `不可用（轻量包或缺文件）` | 轻量包没有 OCR 是设计如此，不是 bug |
| 状态 | `bad · 没有字幕` | 状态条原话 + detail |

断言（`test/diag.test.mjs`，20 条）：推广参数被去掉；`P2/5` 只在多 P 时出现；没填 Key 写「Key 未填」；`ocr` 缺字段就不写这一行；标题/详情里的换行压平；超长标题截 160、详情截 200；坏 URL 原样保留不抛；空对象与 `undefined` 不崩；**输出里绝不出现 `sk-` 或 `apiKey` 字段**。

变异测试：把 `clean()` 里的空白压缩去掉 → 换行那条变红；恢复后 20 条全绿。

切到 `warn` 也显示按钮：用户报得最多的「字幕只有一部分 / 单次取样」都是 warn，只在 bad 时给按钮会漏掉一半报告。

真浏览器验证（2026-11-14，预览页 + 假数据）：把 `navigator.clipboard` 置空模拟「没有剪贴板权限」→ 调用面板按钮的处理函数 → 走 `execCommand('copy')` 兜底并返回成功（状态条回到绿色、按钮收起），复制到的文字是：

```
bili-notes ? · 2026-11-14T12:15:07.806Z
页面: http://127.0.0.1:8799/video/BV1TESTPREVIEW
标题: 光合作用 · 假数据预览
字幕: stable · ai-zh · 60 句
状态: bad
```

版本号显示 `?` 是因为预览页的假 chrome 没有 `getManifest`；「端点 / 模型 / Key」那两行由 background 的 `diag` 消息提供，预览页没有这个假接口，所以只由单测覆盖。

真扩展验证（2026-11-14，真 Edge）：正常态下 `#btnDiag` 带 `hidden` 类（不占位）；把状态切成 `warn` 后按钮立刻出现（实测位置 1250,45、宽 61×23）、`#statusText` 同步成 `字幕只有一部分（真机测试）`。

**点击也验了**：CDP 给 `https://www.bilibili.com` 授予 `clipboardReadWrite`，`Page.bringToFront` 让文档获得焦点，再用 `Input.dispatchMouseEvent` 在按钮坐标上真点一下 → 状态条变成「诊断信息已复制，贴到 issue 里就行」，剪贴板里读回来的原文是：

```
bili-notes 1.0.0 · 2026-11-14T12:28:29.839Z
页面: https://www.bilibili.com/video/BV1GyZYYNErW/
标题: 我的世界克苏鲁全集：一口气看完
字幕: stable · ai-zh · 2132 句
状态: warn
```

顺带验到一条真实的失败路径：文档没有焦点时剪贴板写不进去，面板会显示「复制失败：请截图这段面板状态」——这是设计好的兜底，不是崩溃。（`navigator.clipboard.readText` 在无焦点时抛 `Document is not focused`，所以自动化要先 `Page.bringToFront`。）

## 十五、换视频时旧回包串进新视频（2026-11-16 真机 before/after）

现象：一个视频整理到一半，点右侧推荐换片，新视频里冒出一条上一个视频的笔记，刷新还在。

机制（代码证据）：`runQueue` 里 `const res = await callWithRetry(...)` 之后无条件 `state.notes.push(note)` + `save()`。回包期间 `boot()` 已经把 `state.notes` 清空、`state.bvid / state.meta` 换成新视频 ⇒ 旧笔记被写进新视频的 IndexedDB（键 `bvid:cid`）和检索索引 `bnidx:<bvid>:<cid>`。同类没守卫的点还有 `checkReadability`（会把旧视频的字幕缓存成新视频的 `sub|<bvid>:<cid>`）、`hydrateNotes`、`generateSection`、`maybeSections`、`saveNow`（meta 还没解析时写出 `BVxxx:` 这种半截键）。

修法：`boot()` 里每次 `const seq = ++bootSeq`；每个 `await` 之后先比 `seq !== bootSeq`，不一致就整个丢弃。

| 同一流程（BV1L7xm64EHP 点「总结这段」→ 200ms 内点推荐卡片跳到 BV1REx46NEc4；真 Edge 157 + 真 Key + 真模型） | 结果 |
| --- | --- |
| 未加守卫（HEAD 0cf052a） | 日志 `{"kind":"res","reqBvid":"BV1L7xm64EHP","nowBvid":"BV1REx46NEc4","t":0}` 紧接 `{"kind":"push","t":0,"nowBvid":"BV1REx46NEc4"}`；新视频笔记数 0 → 1（另 1 条是新视频自己的） |
| 加守卫后 | 日志 `{"kind":"res",...,"same":false}` 紧接 `{"kind":"stale-abort",...}`，没有 push；15 秒采样期内新视频笔记数不变 |

为什么必须用点推荐卡片：B站 是 pjax 站内导航（同一 document，前后 `window.__mixMark` 都是 777）。整页 navigate 会销毁文档，旧回包根本回不来，也就测不出这个 bug。

> 诚实记录：这次只防「以后不再串」。已经被写脏的库（旧视频笔记躺在另一个视频下面）不会自动认出来——那需要人工删。

## 十七、时长对上、内容不对（2026-11-16 发现）

闸门能挡住「时长明显不对」的错文件，挡不住「时长刚好对」的错文件。这一条是实际撞上的，不是推演。

| 项 | 实测 |
|---|---|
| 课程 | 【从零开始的 AI 学习】第 23 集 S2-8「感觉模型降智了怎么办？」 |
| BV / cid | BV1Gu4L6iEdc / 43393483954，标题与 UP 主都对，API 时长 482 秒 |
| 字幕返回 | 一份**水蛭解剖**视频的字幕：宽体金线蛭、吸血型与非吸血型齿结构、侧盲囊、雌雄同体异体受精、水蛭素 |
| 闸门结论 | 通过（覆盖比落在 0.85~1.10、结构正常、取样稳定） |
| 后果 | 学习包里多出 12 个与课程无关的概念（103 → 剔除后 91） |

结论：**覆盖比只证明「这份字幕的长度和这个视频差不多」，不证明「这份字幕属于这个视频」**。当前三道闸门（存在性 / 时长 / 结构）加投票，挡的是「明显不对」和「取样不稳」，不挡「长度刚好吻合的另一个视频」。

处置与取舍：
- 学习包导出时人工剔除这 12 个概念，并在这里留痕，不假装没发生。
- 没有加自动判据。想过「字幕词表与标题/简介的重合度」，但课程标题常常不含正文术语（「感觉模型降智了怎么办」与水蛭字幕的重合度可能比与正经字幕还低），误杀风险大于收益，暂不实现。
- 如果以后要做，正确做法是**提示而不是阻断**：面板上标一句「这份字幕和标题几乎没有共同词，可能是别的视频」，让用户自己判断，而不是替他判定。
- v1.4.6 先落了最保守的一档（标题词一个都命中才提示，`titleCheck.tokens >= 6 && hits === 0`）。但这个错样本本身是 **16 个标题词命中 5 个（0.31）**，所以**连这条提示也不会触发** —— 它只覆盖「完全不搭」的极端情况，别把它当成归属校验。三样本实测 0.29 / 0.29 / 0.31，对的错的无法区分，这是「不做判据」的直接依据。

同一次导出里还有一类噪声：S2-1（BV1Y8aL6SEit）有 6 个概念是 UP 主闲聊（喇叭破音、驱动卸载、英特尔智音技术、CPU 故障判定、外置声卡），字幕确实是这个视频的，只是内容与课程主线无关 —— 这属于概念抽取的取舍问题，不是数据错误。

## 二十、字幕「内容对不上」：能提示到什么程度（2026-11-16）

起因：用户在日用 Edge 上看到一个视频，面板写「单次取样（未复核）」，但笔记内容是另一个视频（69 元手办开箱）的。这跟 S2-8 的水蛭字幕是同一种病：**时长对得上，内容不是这个视频的**。

| 视频 | 标题 | 闸门判定 | 标题词 | 命中 | 比例 |

## 二十一、缓存的字幕能不能重新核对（2026-11-16，1.4.8）

起因：用户报过一次「时长对得上、内容却是另一个视频的」字幕。当时只有一个「单次取样 → 再取样」入口，而**从本地缓存恢复的字幕不经过闸门**，一旦某次取到错文件并落了缓存，之后就永远是它，界面上也没有任何重新取样的入口。

先试了「内容级判据」（字幕用词 vs 标题/标签/简介/弹幕的重合度），实测分不开，放弃：

| 样本 | 字幕 n 句 | 与标题+标签+简介的重合 | 与弹幕的重合 |
| --- | --- | --- | --- |
| BV1Gu4L6iEdc 模型降智（这轮取到的是正确字幕） | 237 | 0.106 | 0.255 |
| BV1BgH36DE7y 别再手动帮 AI 点测试 | 300 | 0.061 | 0.320 |
| BV1pwnj6BEMP 给你一个学 AI 的理由 | 161 | 0.167 | 0.208 |
| BV1GyZYYNErW 我的世界克苏鲁（字幕正确、内容与标题用词几乎无关） | 2132 | **0.002** | 0.393 |

⇒ 正确字幕自己就能低到 0.002，错字幕落在 0.1~0.3 区间里看不出来；这类阈值只会误杀。**没有上线任何自动判据**，改做「给用户一个能自己核对的动作」。

改法：从缓存恢复时标记 fromCache=true，工具栏的「再取样」变成**「重新核对」**（single 时仍叫「再取样」）。点它强制重跑闸门：

- 新取样通过（stable / single）→ 用新的，缓存被覆盖；
- 新取样没通过 → **退回原来那份**，状态条写「重新核对没通过（原因），先用上次那份」，不会把本来能用的字幕弄丢。

真机验证（dist 下 edge-profile 已登录，端口 9703，视频 BV1Gu4L6iEdc cid 43393483954）：

| 步骤 | 观察 |
| --- | --- |
| 打开页面（有缓存） | verdict single、cache:true，按钮文字「重新核对」、可见 |
| 往 IndexedDB 写一条假的错字幕（宽体金线蛭 / 侧盲囊 / 水蛭素），刷新 | verdict stable、cache:true，面板显示的就是那份假字幕（恢复路径忠实），按钮仍可见 |
| 点「重新核对」 | cache:false，字幕变回真实 237 句（首句「明明用着的模型」），假字幕里的「水蛭」没有残留；本次接口只给到一份，verdict 落 single，按钮变「再取样」 |

诊断信息（复制诊断）多一行：`字幕来源: 上次存下来的（点「重新核对」可重新取一份对照）`，便于看 issue 时分清「这次取到的」还是「老缓存」。

## 二十四、面板顶部只留一张卡：课程条与掌握度合并、掌握度默认收起（2026-11-16，1.4.11）

问题不是某处坏掉，是**叠**：系列视频页，面板顶部依次是课程条（54px）、掌握度条（34px，每次开页都自动展开成 61px 起）、首屏卡片，再往下才是笔记。三层横条加起来把第一屏几乎吃掉。

| 改动 | 做法 | 真机实测（BV1BgH36DE7y，1280×800） |
| --- | --- | --- |
| 合成一张卡 | `.course:has(+ .mast:not(.hidden))` 去掉下半圆角，`.mast` 上移 1px、去掉上半圆角 | `courseBottom 126` / `mastTop 125`（1px 重叠，两张卡贴成一张，上半灰底、下半白底） |

为什么不用 `:has()` 之外的办法：不动 DOM（掌握度节点还在课程条后面），所以「课程条隐藏时掌握度自己还成立」这条老逻辑不用改；`:has()` 在 Edge 157 / Chrome 105+ 都有，扩展本来就只跑这两家。

| 首页 | 无 | — | 0 |
| `/space/2`（个人空间） | 无 | — | 0 |

结论：`content_scripts.matches` 只写了 `https://www.bilibili.com/video/*`，所以番剧 / 直播 / 首页 / 空间**本来就没有面板**，这是设计不是 bug，而且这些页面上没有任何异常抛出（内容脚本压根没注入）。

### 番剧能不能顺手支持？——结论是不做

查过接口：`pgc/view/web/season?ep_id=<episode_id>` 的 `episodes[]` **是带 `bvid` / `aid` / `cid` / `duration` 的**（实测「小羊肖恩 第七季」ep7702131 → `bvid BV1nQWt6yE1W`、`aid 117585987242252`、`cid 43462886092`、`duration 421000`），所以技术上把 ep 映射成 bvid+cid 就能复用现有闸门。

但 `x/player/v2` 用 `ep_id` 直接查会返回 `code -400`（必须给 aid+cid），而且拿 aid+cid 查回来的 `subtitles` 是**空数组**（该合集连取 3 集都是 0 条）。番剧在 B站 主要靠烧进画面的硬字幕和弹幕，要读就得做 ASR —— 而 ASR 是明确不做的（见 D12）。

所以「番剧页没有面板」写进已知不足，不投入。哪天真要支持，得先证明某批番剧确实有可读的 CC 字幕。

### 键盘可达：笔记能 Tab 到、能回车展开

笔记原来只有鼠标能展开（`.h` 是 div，点一下切换），键盘用户和读屏用户拿不到。改法：

- `.h` 加 `role="button"`、`tabIndex=0`、`aria-expanded`、`aria-label`（时间 + 摘要 + 「可展开/收起」），`Enter` / `Space` 切换；
- 时间戳 `.t` 加 `role="link"`、`tabIndex=0`、`title="跳到这一秒"`，`Enter` / `Space` 跳转并且 `stopPropagation`（不许顺带展开）；
- 焦点环用 `outline: 2px solid var(--bnaccent); outline-offset: -2px`，跟 B站 蓝一致。

真机验证（BV1GyZYYNErW，119 条笔记）：`Enter` → `aria-expanded` false→true、`open:true`、焦点留在 `.h`；再按 `Space` → true→false；鼠标点 `.h` → 又 true；点第 3 条的时间戳「1:08」→ 视频从 0.1 秒跳到 68.9 秒、该笔记**没有**被展开。

## 二十七、字幕对不上时也能「再试一次」（2026-11-16，1.4.15）

以前只有「单次取样」和「用的是缓存」这两种状态会出现重取按钮；`rejected`（取到了、但对不上）反而是最该重试的一种，却没有入口——用户只能眼睁睁看着「字幕和视频对不上」。

而「重试有用」这件事我们早有实测依据：批量导出 S2 时第一次 9 集只过 4 集，第二轮把 5 集全救回来了（2 集「没有文件地址」、1 集「每次都不一样」、2 集时长对不上）。B站 同一个 (aid,cid) 连取几次会返回不同的字幕文件。

现在 `verifyReasons()` 把三种情况分开：

| 状态 | 按钮 | 文案 | 为什么 |
| --- | --- | --- | --- |
| `fromCache` | 出现 | 重新核对 | 现在用的是很久以前存下的那份，可能根本不属于这个视频 |
| `single` | 出现 | 再取样 | 只取到过一份，没交叉核对 |
| `rejected` | 出现 | 再试一次 | 这次对不上，B站 可能下次给对的那份 |
| `need-login` / `no-subs` / `empty-url` | **不出现** | — | 重跑一百次也是同一个结果，给了按钮等于骗人 |

真机验证（`/video/BV1LpD3YsETa/?p=2`，这一集的字幕确实是别人家的）：状态条「字幕和视频对不上」→ 按钮「再试一次」可见 → 点击后「检查字幕 1/5 …」→ 12 秒后仍回到「字幕和视频对不上」，按钮再次可见（这一集本身就没有对得上的字幕，属正确结果）。

顺带确认了一件之前没验过的事：**页内切分 P 时面板会跟着走**——点第 2 个分 P，`#pLabel` 从 `P1/2` 变 `P2/2`、状态条立刻变「检查字幕 5/5 …」，没有把 P1 的字幕留在 P2 上。

## 二十九、花钱这件事：默认不自动、有闸、按真价显示（2026-11-16，1.4.17 真机）

用户问「为什么额度消耗极快」。先把账算清：一次「整理一段」发出 system 546 字符（每块重发）+ user 890 字符 + 输出约 623 字符，实测 **1010 token/段**；按 DeepSeek 现价（输入 ¥2/M、缓存命中 ¥0.2/M、输出 ¥3/M），1 小时视频约 86 段 ≈ ¥0.20。而旧代码把花费按 `tokens / 1e6 * 1.5` 平摊显示，同一份账只显示 ¥0.13 —— 低报约三成。

代码层的四个漏点与改法：

| 漏点 | 原来的行为 | 现在 |
| --- | --- | --- |
| 自动跟播就调模型 | `onTimeUpdate → runQueue()`，无开关、无上限、无询问 | 默认关；第一次走完一段才问一次「边看边整理」，答过记住（storage `bn.autoNotes` + localStorage `bn.autoAsked.v1`）|
| 没有额度上限 | 一直调用到队列空 | 单视频 / 每日两个 token 上限（默认 120000 / 600000，设 0 不限），到线停并说清怎么继续；点「继续整理」只放行一段 |
| 重试太宽 | `RETRYABLE` 含 `http`，400 这类永久错误也重试 3 次，每次全额计费 | 只重试 rate-limit / network / timeout 与 5xx；`maybeSections` 同一节 3 次降为 2 次 |
| 花费显示偏低 | `tokens / 1e6 * 1.5` | 分项计费：输入 / 缓存命中 / 输出各按真价，并按 usage 里的 `prompt_cache_hit_tokens` 扣减 |

真机验证（真 Edge 157 + 真扩展 1.4.17 + 真模型，视频 BV1twZ4YzEmv，65 段）：

| # | 动作 | 结果 |
| --- | --- | --- |
| 1 | 默认状态看一段新内容（2 倍速播 30 秒） | 面板出现询问条，`chat` 消息 **0 条**（只有一条本地 OCR 的 `ocr` 消息），笔记数不变 |
| 2 | 点「只在我点了才整理」 | `bn.autoNotes=false`、询问条收起、状态条「只在你点「总结这段」或「整理全片」时才调用模型」 |
| 3 | 打开自动后再看一段 | `chat` 2 条、笔记 11 → 13、`bntok:2026-11-16` 落盘 3274 |
| 4 | 单视频上限设 1000 token 后点「整理全片（55 段）」 | 一段都没发（已用量 13k 早就超过），状态条「到上限了（单视频上限 1.0k token…）」，队列 55 段原地挂起、`queueHold=true` |
| 5 | 成本显示 | `17k ≈ ¥0.034 · 每段 ¥0.003`，title 写「输入 16472 token（其中缓存命中 640）+ 输出 803 token」；同一份账按旧的 1.5/M 公式是 **¥0.0259**，旧显示低报约 24%~31% |

边界（写清楚，避免误读）：

- 上限拦的是「自动跟播」和「整理全片」这类批量路径；你亲手点某一段的「总结这段」不拦——那是一次明确意图，不是失控。
- 上限单位是 token 不是钱：汇率会变，token 不会。显示的钱只是同一份 token 按当前价折算。
- 还有一个已知的大头不在插件里：账号面板「今日已用 ¥15」主要是 agent 会话每轮重发上下文。插件单视频是 ¥0.0x 级，想分账就给插件单独建一把 key。
- 没做的：prompt 瘦身（system+schema 占输入四成）、把块从 45 秒拉到 90 秒（约省四分之一调用）、把 machine 模式的三行提示移出 system 以保住前缀缓存。

## 三十、概念视图：一门课到底讲了哪些概念（2026-11-16，1.4.18 真机）

以前概念只存在于缓存里（`chrome.storage.local` 的 `bnc:<cid>`），人和 agent 都要先导出学习包才看得到；面板上只有一条「掌握度」。1.4.18 把「概念」做成面板里的第三块视图：按集分组、每个概念带定义与「第几集第几秒」的逐字原话，点原话跳回那一秒。

数据源与判据：

- 合并用 `window.BnConcept.merge`，所以跨集同名 / 别名会合成一张卡；`跨 N 集` 徽标就是合并后锚点落在几集。顺序按「跨集数 → 锚点数 → 最早出现」排，跨集概念排最前——它们是知识点之间的连接。
- 去噪只标灰不删：`suspect = 只在一集出现 且 概念名/定义与集标题没有字面重合`。中文按 2 字滑窗、英文按整词比。
- 掌握度只读 agent 回流的 `study-state`（`bnstudy:<course_id>`），不自己判。

真机验证（真 Edge 157 + 真扩展 1.4.18 + `dist\edge-profile`，BV1BgH36DE7y，S2 全 9 集已有 `bnc:` 缓存）：

| # | 指标 | 实测 |
| --- | --- | --- |
| 1 | 工具栏入口 | 概念缓存存在时按钮在工具栏（`概念 ▸`）；title「这门课 103 个概念 · 点一处原话跳到那一秒」 |
| 2 | 规模 | **103 个概念 / 9 集分组 / 215 个时间锚点**（DOM 里渲染 208 条原话 += 每条最多只列 3 处） |
| 3 | 跨集合并 | 跨集概念 2 个（`agent工具` 落在 S2-4 与 S2-6；`agents.md` 落在 S2-4 等），徽标「跨 2 集」 |
| 4 | 去噪标记 | 29 个标灰（`只在这一集出现、集标题里也没有这个词`），不删 |
| 5 | 掌握度回流 | 写入真实 `study-state.json`（91 概念：懂 5 / 半懂 11 / 没考 75）后，概念卡上立刻出现 **16 个徽标**（5 懂 + 11 半懂），无需刷新页面 |
| 6 | 点原话跳转 | 点当前集 S2-6 的 `1:02` → 视频从 2.9s 跳到 62.8s，URL 不变（同一集只 seek） |
| 7 | 只看跨集 | 勾上后列表从 103 条收到 2 条 |
| 8 | 工具栏不换行 | 有概念的课程页 `.acts` 高 **32px**（一行）；没概念的单视频 31 集课程页同样 32px |

两个真问题（都是真机才暴露的）：

1. **掌握度徽标一直是 0**：`loadStudyStates()` 只重画掌握度条，不重画概念列表；于是「应用学习状态」后概念卡上的「懂 / 半懂」要等刷新页面才出现。修法：`loadStudyStates` 回调里同时 `refreshConcepts()`。
2. **工具栏又换行（回调 1.4.10 的做减法）**：新增第 6 个按钮后，`.acts` 从 32px 变成 61px/两行。修法：概念还没抽出来时（此时它只是个「抽概念」的次要动作）把按钮收进「⋯」；已有概念才放回工具栏。实测 31 集课程页 `⋯` 展开是 设置 / 再取样 / 诊断 / 概念，`.acts` 仍 32px。

顺便纠正一处误导：单视频如果属于一个大合集、又没勾选集，「抽概念」预估价算的是**整门课**（实测 31 集 59 小时 59 分 → 737 次调用 ≈ ¥4.20），文案原来没说范围。现在写上「还没勾选集，会抽整门课 31 集；想省钱先在清单里勾几集」。

未验证 / 边界：

- 概念本身是模型抽的，会漏也会多；这个视图只是把已有概念排好、给出处，不提高召回。
- 只有 1 条视频真机跑过（同一个 9 集课程）；其他课程的概念数、去噪比例没有样本。
- 概念缓存按 `cid` 存，换视频不串（详见第十六节换视频串笔记的修复）；但**已被写脏的旧缓存不会自愈**，要重新抽。

## 三十一、导出之后：把「交给 agent 那句话」放进剪贴板（2026-11-16，1.4.19 真机）

导出学习包后，最难的一步不是抽概念，是「agent 怎么知道文件在哪」。浏览器只肯把文件放进下载目录，扩展也拿不到绝对路径（`<a download>` 的 `filename` 只能指定下载根目录里的相对路径）。所以 1.4.19 在导出之后多做一件事：把一句可以直接粘给 agent 的话写进剪贴板。

那句话的形状（`src/packhandoff.js` 的 `text()`）：

```
我刚用「B站字幕笔记」导出了学习包「【从零开始的 AI 学习】（S2 · 2 集学习包）.json」（同目录还有「…md」，是给人看的版本）。
请用 bili-study 带我学这门课：先找到这个文件（默认在浏览器下载目录，Windows 是 %USERPROFILE%\Downloads，macOS 是 ~/Downloads；找不到就问我路径，别猜），读之前确认 spec 是 bn-study-pack/1，然后按下面的目标裁剪、出依赖图和学习顺序，再用逐字原话考我。
课程：【从零开始的 AI 学习】（S2 · 2 集）
目标：我还没写，请先问我这次想学到什么程度，再开始裁剪。
```

没写目标时它会反过来问，而不是自己编一个；没勾选集时不写「0 集」。

真机（真 Edge 157 + `dist\edge-profile` 已登录 + 真扩展 1.4.19，BV1BgH36DE7y，勾 S2 前两集点「交给 agent（2 集）」）：

| # | 指标 | 实测 |
| --- | --- | --- |
| 1 | 状态条 | 「学习包已导出 · 2 集 · 9 条笔记 · 24 个概念 / 55 个时间锚点」 |
| 2 | `bn.packLast` | 落盘 `{at, copiedAt:"", course:"【从零开始的 AI 学习】", episodes:2, goal:"", jsonName:"【从零开始的 AI 学习】（S2 · 2 集学习包）.json", mdName:…, scope:"S2", text:…}` |
| 3 | 剪贴板 | 这次没写成（`copiedAt` 空）——CDP 驱动的标签页没有焦点。这是**设计内的失败路径**：记录照写，之后点扩展图标会自动补一次 |
| 4 | 弹窗卡片（另一次真机） | `{hidden:false, meta:"【从零开始的 AI 学习】（S2 · 2 集学习包）.json · 2 集", note:"已复制。去 agent 里粘一下就开讲…", btn:"再复制一次", write:"ok"}`；`copiedAt` 写入 |

实测挖出的一个真 bug（不修就是「点完没反应」）：

第一次跑，状态条永远停在「抽概念 2/2 · 第 16 集」，等了 320 秒也没有「学习包已导出」，`bn.packLast` 一直是 null。原因不是慢，是 `await navigator.clipboard.writeText()` 在**没有文档焦点的页面里 Promise 永远不 settle**（既不 resolve 也不 reject）。修法两条：

1. 记录先写 storage，再尝试剪贴板——剪贴板失败不该把整张卡一起丢掉；
2. `writeText` 用 `Promise.race` 加 1.5 秒超时，超时按「没写成」处理，让弹窗之后补。

修完同一条路径 **23 秒**跑完（概念命中缓存），状态条正常、记录正常。

边界：

- 这句话只是「告诉 agent 去哪找」，不保证找得到。下载目录被改过、文件被改名、agent 在别的机器上，它还是会问你要路径——所以那句话里明确写了「找不到就问我路径，别猜」。
- 不给 `downloads` 权限就读不到下载目录的绝对路径（那是更准的做法，但要新增权限、商店要写理由）。当前取向是：零新权限 + 用户点一下图标兜底。
- 弹窗自动复制只在「记录里没有 copiedAt」时触发，不会每次开图标都覆盖用户剪贴板。

3. **「学习页」按钮永远不出现**：它的显隐只写在 `syncMultiBtn()` 里，而 `syncMultiBtn` 由 `syncMeta` 阶段调用——那时候 `refreshCourse()` 还没把 `courseModel` 建好，之后没人再刷这个按钮，于是一直带着 `hidden`（点都点不到）。修法是新增 `syncStudyBtn()` 并接到 `refreshCourse` 的四条出口（两条早退、成功结尾、catch）。

### 两条环境教训

- **改了 `background.js` 必须重载扩展**：跑着的 MV3 service worker 还是旧代码，此时 `sendMessage({type:"openStudy"})` 会安静地返回 `undefined`（不报错），看起来像「新分支没写对」。`{type:"diag"}` 这种老分支照常正常，最容易误判成「消息通道坏了」。
- **CDP 找扩展上下文别硬编码扩展 id**：同一台机器上装着沉浸式翻译等扩展，先正则抠所有 `chrome-extension://<32 位>/` 再排除已知 id，比写死更快；`Runtime.evaluate` 必须带 `contextId`，隔离世界的 `name` 就是扩展名「B站字幕笔记」。

## 三十六、右栏「今天先看这几个」：按掌握度排复习队列（1.4.24）

### 这一遍验收踩到的两件事（重要）

1. **`dist\edge-profile` 这份测试 profile 后来坏了**：内容脚本完全不再注入（CDP 里只剩沉浸式翻译和 Bili SyncPlay 的隔离世界），存储目录 `Local Extension Settings\mdpphogn…` 也整个消失。同一个仓库、同一份 manifest，换一个**新建 profile** 立刻正常 ⇒ 判「扩展坏没坏」先换干净 profile，别在同一份 profile 里反复怀疑代码。

- `view` 不认识就当作「全部」，学习页不会因为一个脏参数白屏。


## 三十八、学习页中栏「按概念」视角（1.4.26）

### 这一遍卡住的真正原因（值得记住）

### 这轮的两个真问题

1. **「还没弄懂」按钮被排法处理器抢走了**：它复用了 `.mbtn` 样式与类名，而中栏排法的接线是 `querySelectorAll('.mbtn')`，于是点过滤开关会先跑排法逻辑——`b.getAttribute('data-mode')` 是 null ⇒ mode 掉回 `ep`。现象非常迷惑：点一下「还没弄懂」，中栏变回按集、按钮自己消失、数字归零，看起来像「过滤没生效」。修法是把接线收窄到 `.mbtn[data-mode]`（连线里的 `.on` 重置也一起收窄）。教训：**复用样式类名时，别让行为选择器和样式选择器共用同一个类**。

### 三个坑（都吃到了）

1. **`Start-Process` 起的监听进程会跟着父 pwsh 一起没**。`install.ps1` 第一版用 `Start-Process -WindowStyle Hidden`，脚本退出后 `Get-CimInstance` 一个都查不到，日志也没有第二条「启动」。改成 `Invoke-CimMethod -ClassName Win32_Process -MethodName Create` 才活下来（本次 PID 36972）。
2. **查进程会查到自己**。`Where-Object { $_.CommandLine -like "*bn-agent-bridge.ps1*" }` 会匹配到正在执行这条查询的 pwsh（查询语句本身就含这个字符串），于是「进程在跑」是假阳性。加 `-notlike "*-Command*"` 排除。
3. **PowerShell 反引号不能出现在 JS 模板字符串里**。写 `-join "`n"` 直接把生成器的模板提前结束，报 `Unterminated template`；改用 `[Environment]::NewLine` / `[char]34` 拼引号。

### 为什么不做「全自动发送」

本机 DSH 的 web 接口要鉴权：`/api/health`、`/api/sessions` 不带 token 都是 401。要绕过去，要么从 CDP 里捞 boot token，要么做 UI 自动化——两者都会在用户没看着的时候替他按下回车，而 DSH 一升级就可能失效。
停在「窗口到前面、文字在剪贴板」，把最后一步留给用户，既稳又不会误发。这条边界写进了 `tools/agent-bridge/README.md`。

### 边界

- 只认**下载目录 + 文件名前缀**，不看内容；下载目录可用 `-DownloadsDir` 改。
- 拉窗口会抢焦点——这是它的用途，但用户正在打字时会打断。
- 找不到窗口只写日志（agent 没开、进程名不叫 `DeepSeek` 都会这样，用 `-ProcessLike` 改匹配）。
- 只在 Windows + PowerShell 5.1 上验过；macOS 没有对应实现。

### 两个坑

1. **`process.exit(0)` 不会关掉浏览器**。下一次用同一个端口 `fetch('/json/list')` 会连到上一轮那个还开着的 Edge，读到的是旧页面旧代码（甚至 `localStorage` 里已经有上一轮的 key），于是「改完了没生效」「守门没起作用」全是假象。每次跑前先按命令行 `Stop-Process` 清 `msedge.exe`，并且换一个端口。
2. **改 `content.js` 后旧标签页不会自己换代码**，必须重新加载扩展/重开浏览器；但 `chrome.runtime.getManifest().version` 会是新的——**版本号不能当「代码已生效」的证据**（这条在 1.4.25 又踩过一次）。

### 边界

- 只提醒一次，按 bvid 记；换了视频还会再提醒一次。
- 单集视频、番剧播放页不提醒（`courseModel.kind === 'single'` 或集数 < 2）。
- 提醒只是「告诉你另一个按钮在哪」，不替用户勾集、不替用户点。
