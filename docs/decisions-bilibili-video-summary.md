## 2026-11-16 点图标之后的第一步

用户自己用插件时暴露的问题：「大多数人包括我都是直接点插件按钮，找不到按钮就不会搞了」。当时 `action.default_popup` 指向搜索页，点图标得到的是一个空搜索框 —— 新人会以为这就是全部功能，然后关掉。

做法（不新增权限、不加服务器）：
1. 弹窗顶部先回答「我现在看的这个视频」：已整理过就显示「继续上次 · 已经攒了 N 条笔记」+「打开面板」；没整理过就显示视频标题 + 「不填 API Key 也能导出字幕全文」。
2. 不在视频页就把卡片藏起来，底部「打开当前视频的面板」保留，点了给一句人话提示。
3. 点「打开面板」走已有的 `bnOpenPanel` 消息：收起的展开、自动收起的收回、闪一下边 —— 这条链路（`openPanelFromIcon()`）之前只有 in-page 工具栏图标在用，这里复用。

判据（现在是验收清单 A2）：在任意 B站 视频页点扩展图标，**一眼能看到进面板的入口**，不用猜。
另一条判据来自同一轮对话（A3）：同一视频刷新 / 切走再回来，笔记条数不变 —— 「只要做出来就得在，除非主动删除」是产品承诺，换设备会丢这件事要在 PRIVACY 里说清，不能让人以为有云同步。

# B 站「可核对听课笔记」扩展 — 决策记录

> 这是一份从 2026-11-12 起连续写的**决策/实测记录**（按时间追加，前面的结论后面可能被推翻，翻到最新一条为准）。文中所有「实测」都是在本机登录态下真跑出来的数字，60 条样本的原始数据在 [`test/fixtures/probe-results.json`](../test/fixtures/probe-results.json)。

## 0. 一句话

**一个跟着你听课、边听边写、写完你能核对、看不懂有人话版的笔记工具。**

- 下限（防错）：每条结论都能点回原句。
- 上限（有用）：人话版讲解 + 大纲 + 回答。
- 只有下限等于准确的废话；只有上限等于漂亮的编造。

## 1. 结论摘要

1. **只服务「有可用字幕」的视频**（用户 2026-11-12 拍板）。ASR 兜底不在 v0。
2. 60 条样本实测「第一眼可用」**23%**，且**同一视频多次请求会返回不同的字幕文件**。
3. 所以字幕不能当事实来源，只能当候选：**必须过信任闸门**（§5）才允许出现「可核对」字样。
4. 差异化不在「总结」，在**校验 + 分层 + 可回溯**：现有产品（BibiGPT 等）能把整片字幕一次性喂给模型，但没有人做「跟着播放头增量写 + 每条可核对」。

## 2. 平台实测事实

### 2.1 接口

| 用途 | 端点 | 备注 |
|---|---|---|
| 登录态 | `GET /x/web-interface/nav` | `isLogin` |
| 元数据/分P | `GET /x/web-interface/view?bvid=` | `aid`, `cid`, `pages[]` |
| 字幕列表 | `GET /x/player/v2?aid=&cid=` | **必须用 aid，不要用 bvid** |
| 字幕文件 | `//aisubtitle.hdslb.com/bfs/ai_subtitle/prod/...` | 需 UA + Referer |
| 榜单样本 | `GET /x/web-interface/ranking/v2?rid=&type=all` | 一级分区才有数据 |

- 上述 `api.bilibili.com` 请求在**页面内**（content script 或页面上下文）带 `credentials:'include'` 即可，**不需要 cookies 权限**。
- 字幕文件域 `aisubtitle.hdslb.com` **不发 CORS 头**，页面内 fetch 报 `TypeError: Failed to fetch`；扩展 background（host_permissions）或 Node 可抓。
- 未登录：`need_login_subtitle: true`，字幕 0 条。**登录是硬前提。**
- 频率高时会返回空轨列表（限流特征），必须缓存 + 退避。

### 2.2 字幕数据形态

```json
{ "type": "AIsubtitle", "version": "v1.7.0.4", "lang": "zh",
  "body": [ { "from": 1.08, "to": 4.2, "sid": 1, "location": 2, "content": "……", "music": 0 } ] }
```

- 首轮 20 条样本里，**首轨全是 `lan: ai-zh`（B 站 AI 字幕），0 条 UP 上传人工字幕**。热门 MV 例外，有 12 条语言轨（zh-CN/zh-Hans/zh-Hant/zh-HK/en-US/ja/ko/de-DE/ru/iw/ca/ase）。
- 所以「优先人工字幕」这条策略在真实样本上基本落空，主要工作对象就是 AI 字幕（会有同音字错、断句错）。

### 2.3 可用率（60 条，10 个一级分区各 6 条）

`cover = 首轨末句 to / 当前分P时长`

| 判定 | 条数 | 占比 |
|---|---|---|
| ok（0.35 ≤ cover ≤ 1.15） | 14 | 23% |
| overflow（> 1.15，字幕比视频长） | 17 | 28% |
| truncated（< 0.35，只覆盖开头） | 9 | 15% |
| emptyUrl（有轨但 url 为空） | 9 | 15% |
| noSubs（没有轨） | 11 | 18% |

- **2026-11-14 更正**：上表用的是当时的宽松阈值 0.35~1.15，ok = 14（23%）。现在的闸门是 **0.85~1.10**，同一批数据重算是 ok **10**（17%）、truncated **13**（覆盖 0.40~0.475 的那几条被宽阈值放过了）。对外引用请用 17%，不是 23%。
- **长视频更差**：3081 秒的视频无轨；84 分钟《解三角形》课程无轨（播放器连字幕按钮都没有）；2960 秒的视频只覆盖 9%。
- **多 P 视频**：`view.duration` 是合集总时长，必须用 `pages[]` 里对应 cid 的 duration 当分母（BV16io9YTEqH 有 4 个分P，第 1P 451 秒，总 1798 秒）。

### 2.4 稳定性（最关键）

同一 `(aid, cid)` 在几秒内多次请求，拿到的字幕文件会变。6 条失败样本各重试 3 次的 cover 序列：

| 视频 | 时长 | 三次结果 |
|---|---|---|
| BV1UbZ8YmEP8 | 194s | empty , 1.73 , 8.28 |
| BV17VZpY1ENA | 15s | 14.76 , 12.81 , 17.28 |
| BV1RdZEY8E8T | 115s | empty , 0.92 , 0.92 |
| BV1MXZJYpEuN | 219s | 5.60 , 0.93 , 1.41 |
| BV1MbZnYoEk1 | 100s | empty , 10.63 , empty |
| BV1YTZvYMECW | 227s | 0.04 , empty , empty |

- 194 秒的视频会拿到 1606 秒的字幕文件。
- 两个不同的街舞视频拿到同一首歌的歌词「♪ 突然发现站了好久 ♪」⇒ 错配可能按「同 BGM / 同合集」成簇发生。
- **时长对齐也可能内容不符**：BV1eBZhYhEa9 cover 0.92，内容是歌词，与标题「模仿不同国家的气象主播」无关。
- **接口说有 ≠ 播放器显示**：BV1wyZnY2EHU、BV16io9YTEqH 接口给轨，页面 `.bpx-player-ctrl-subtitle` 不存在。
- 好消息：重试确实能救回一部分（BV1RdZEY8E8T、BV1MXZJYpEuN 各命中一次通过闸门）。

## 3. 原则（不可违反）

1. **引用层只许摘录**：`quote` 必须逐字来自字幕或画面文本，只允许改标点、用「……」省略。
2. **讲解层只许重构，不许新增事实**：专有名词、数字、人名必须在原文出现。
3. **不确定就明说**：字幕来源、覆盖率、是否校验过，全部显式展示。
4. **不静默降级**：没有字幕不是「转圈」，是明确的状态和下一步建议。

## 4. 架构 B′

```
B 站页面 (content script)
  ├─ 页面内 fetch（借登录态，不读 cookie）→ view / player/v2
  ├─ 右侧浮层 UI（跟着播放头）
  └─ 消息 → background (service worker)
        ├─ 抓 aisubtitle 文件（host_permissions）
        ├─ 调 LLM（用户自填 key，直连）
        └─ IndexedDB 缓存

管理入口：选项页（填 key / 选模型 / 开关）
```

- 无自建后端（v0）。
- 不申请 `cookies` 权限，隐私说明可写「从不读取登录凭证」。
- 分发：GitHub Release zip + 开发者模式加载；接口稳定后先上 Edge 商店（免费），再考虑 Chrome。

## 5. 字幕信任闸门（本项目的生死线）

只有通过闸门的字幕，才允许出现在「可核对」语境里。

**判定**
- `cover = lastTo / 当前分P时长`，通过区间 **0.60 ≤ cover ≤ 1.10**（比 §2.3 的统计判据更严）。
- `lines ≥ 10` 且平均句长 ≥ 3 字。

**取样**
- 最多请求 **3 次**，间隔 800~1200ms，取**第一个通过**的结果。
- 同一 cid 两次独立请求文件 sha256 相同 → 标 `stable`；只通过一次 → `single`（界面标「未复核」）。
- 3 次都不通过 → `rejected`，不再重试（本次会话内）。

**缓存**
- IndexedDB：`{bvid, cid, sha, file, cover, attempts, fetchedAt, verdict}`。
- 命中缓存时不重新请求（除非用户手动「重新获取字幕」）。

**状态（界面必须分开显示，不能共用「出错了」）**
1. `noSubs` — 该视频没有字幕轨 → 「该视频没有字幕，无法记录」
2. `emptyUrl` — 有轨但拿不到文件 → 「字幕暂时取不到，稍后重试」
3. `truncated` — 只覆盖 X% → 「字幕只覆盖前 X%，后面的内容无法核对」
4. `overflow` — 字幕比视频长 → 「字幕与视频不匹配，已拒绝使用」
5. `unstable` — 多次取样不一致 → 「字幕源不稳定，本次结果仅供参考」
6. `single` — 只通过一次的 → 正常使用，标「未复核」
7. `stable` — 两次一致 → 正常使用，标「已复核」

## 6. 内容三层

| 层 | 粒度 | 生成方式 | 用途 |
|---|---|---|---|
| 原文层 | 句（带 from/to） | 不生成，全保留 | 引用、跳转、核对 |
| 要点层 | 15~40 秒一块 | LLM 一次出 2~4 条 | 笔记流主体 |
| 结构层 | 小节 / 全片 | 复用块摘要二次压缩 | 大纲、导出 |

不做逐句摘要：450 次调用换更低的分辨率，且单句无语境必编。

## 7. 切块规则

- 目标 6~10 句；硬上限 45 秒、硬下限 15 秒。
- **边界只能落在句子边界**，绝不切断句子。
- 优先断点：字幕间隙 > 1.2 秒 → 话语标记（那么/接下来/首先/总结一下/我们来看）→ 疑问句结束。
- 块 id = `(bvid, cid, 起始句序号)`。

## 8. 讲解层 prompt v1

**输出 schema**

```json
{ "block_summary": "≤40 字总纲",
  "points": [ { "quote": "逐字摘录", "sentence_ids": [12,13], "start": 120.4, "end": 128.9,
                "plain": "≤80 字人话", "kind": "conclusion|definition|example|step|question",
                "terms": [{"term":"协方差","plain":"两个东西是不是一起动"}], "analogy": null } ],
  "one_thing": "如果只记一件事" }
```

**8 条硬规则**
1. `quote` 逐字，只许改标点，跨句用「……」。
2. `sentence_ids` 必须真实存在，且与 `start/end` 对得上（容差 0.5s）。
3. `plain` 里的人名/数字/专有名词必须在 `quote` 或本块字幕里出现过。
4. 禁止评价性形容词（非常重要/极其关键/深刻/核心/重大意义…）。
5. `plain` 单句 ≤25 字。
6. 口水词（啊/嗯/那个/就是说）不进 `quote` 以外的地方。
7. 每块最多 4 条 `points`。
8. 全废话块返回空数组 + `block_summary`「本段无实质内容」。

**自动校验（不合格直接丢弃）**
- `quote` 归一化后必须是字幕的连续子串；
- id/时间戳一致（±0.5s）；
- 实体越界（数字、英文串、书名号内容）；
- 长度（`plain` ≤80 字，单句 ≤25 字）；
- 评价词黑名单（允许带条件的评价：只/仅/如果/当/因为/否则/除非 需在评价词后 20 字内）；
- 每块 ≤4 条，按 `start` 排序截断。

**语气**
- 假设读者是新手但不笨。
- 用「它在回答什么问题」开头，不用「它是什么」。
- 能用动词不用名词化。

**反例**（要避免）
> 讲师深入阐述了协方差矩阵的统计学意义，揭示了变量之间的协同变化规律，对于理解多变量分析具有重要价值。

三个毛病：拔高、名词堆砌、纯评价。

**参数**：temperature 0.3；max_tokens ≈600/块；讲解层模型档位比摘要层高一级。

**演进**：v1 本文 prompt → v2 把答错的段落做 few-shot 反例 → v3 个性化（红线：不得降低可核对性）。

## 9. 画面通道（OCR）

- 结论：**需要画面 ≠ 需要 VLM**。信息型画面 90% 承载文字（PPT/代码/公式/报错），OCR 够用且天然可核对。
- 取帧：canvas `drawImage(video)`——只拿解码像素，**无弹幕、无播放器 UI**（截屏/tabCapture 都做不到）。
- 抽帧：稳定帧（连续 2 秒画面不变取中间）+ 场景切换 + **指代词触发**（字幕出现「这个图/这里/你看/这个公式」）。
- 去重：相邻帧 OCR 文本相似度 >0.9 丢弃。
- 分辨率硬约束：**360p 不可用，必须 720p+**（中文实用下限约 20 像素字高）。
- 融合：画面文本作为平行通道，喂模型时标 `[画面 12:06]`，`quote` 可引用两个来源，界面标「原话」或「PPT 上写的」。
- 按分区开关：知识/科技/课程默认开；访谈/播客/音乐/影视/游戏默认关。
- 排期：**v1 后半段**，不在 v0。

## 10. 检索与问答

- 三路召回：时间邻近（播放头 ±3 分钟，×1.5 权重强制入选）+ 关键词 BM25（×1.3）+ 语义向量（默认关）。
- 时间表达式解析：「19 分钟处」「开头十分钟」直接定位。
- 取 top 5~8 块，带时间戳进上下文。
- 问答必须给可点秒数；引用块不够时明说「这段没讲到」。

## 11. 界面

- **页面内右侧浮层抽屉**（不用 sidePanel，避免挤窄页面、可跟随 B 站深色主题），默认 380px，可拖拽并记忆，收起为 44px 竖条。
- 结构：状态条(44px) → 可折叠全片大纲（8~12 条，当前项带 ●）→ 滚动笔记流 → 底部提问框。
- 五条决定：
  1. 页面内浮层；
  2. 新条目**底部追加**；
  3. 默认跟随滚动，用户手动上滚即锁定 15 秒并出现「回到当前 ↓」（绝不抢滚动条）；
  4. 未观看用**虚线占位条 + 可点击**，不留白；
  5. 问答回答**就近插在笔记流里**，不另开对话页。
- 三个特殊状态：gap 虚线占位、走神回来横幅、「冷却中」用灰线「· · · 正在整理 22:10–22:48」而非 spinner。
- 状态条只放四件事：字幕来源+可信度、队列状态、花费（悬停看金额）、设置齿轮。
- 首次进入默认展开一次，之后记住用户选择。

## 12. 走神与未观看

统一数据模型：`unfocused: [{start, end, reason}]`，`reason ∈ {skipped, hidden, paused, locked}`。

- 信号（v1 只认三个）：切走标签页/最小化 > 90 秒；手动暂停 > 2 分钟；锁屏/休眠立即算。
- 回来后**可关闭横幅**（不弹窗、不暂停、不滚动）：「你离开了 5:20 · 这段讲了 3 件事 [展开补课] [忽略]」。
- 补课模式只显示一句话级要点，每条带 [去看这段]（可选 1.25 倍速）。
- 防烦：同一次播放只自动弹一次；关闭后 24 小时内同视频不再弹；8 秒后缩成小图标。
- 只记时间戳与原因，不记录去了哪里；可整体关闭。

## 13. 成本护栏

- 只总结**实际播放过的区间**；未播区记 gap，默认不总结。
- 单视频硬上限（按字数估，如 3 万 token）。
- 并发 ≤3，RPM 限流，429 指数退避并显示「排队中」。
- 界面常驻显示「已用 X 万 token ≈ ¥Y」。
- 缓存键 = `视频 id + 分P + 字幕 sha + prompt 版本`。
- key 存 `chrome.storage.local` 明文，设置页写明风险，提供「仅本次会话」选项。

## 14. 失败模式与文案（七种，不能共用一句「出错了」）

| 状态 | 文案 |
|---|---|
| 未登录 B 站 | 「请先登录哔哩哔哩，字幕需要登录才能获取」 |
| 无字幕 | 「该视频没有字幕，无法生成可核对的笔记」 |
| 字幕截断 | 「字幕只覆盖前 X%，之后的内容无法核对」 |
| 字幕不匹配/不稳定 | 「字幕与视频不匹配（或多次获取结果不一致），本次结果仅供参考」 |
| API key 未填 | 「请先在设置里填写模型 API Key」 |
| key 失效/超额 | 分开两种文案，附「重新填写」入口 |
| 字幕接口改版 | 明确错误码 + 「请检查扩展更新」 |

## 15. 明确不做

- 多平台（YouTube/抖音等）
- 手机端 / 移动浏览器
- 画面理解（VLM、帧 OCR 之外的东西）
- 自动发布、直播、番剧
- 外语翻译字幕
- 全屏独立笔记页、底部时间轴缩略图、笔记编辑（v1 只读）
- 悬浮球/桌面通知、多标签页同步、自动暂停视频

## 16. v0 验收（全过才算成立）

1. 打开一个有可用字幕的视频 → 闸门判定正确（stable/single 至少一种），显示字幕来源与覆盖率。
2. 未登录时明确提示登录，不静默失败。
3. 无字幕视频显示「该视频没有字幕」，且**不**调用模型。
4. 播到第 1 块结束 → 侧边出现 1 条带时间戳的要点，点它能跳回该秒。
5. 每条要点的 `quote` 能在字幕里原样找到（自动校验通过率 100%，因为不过的直接丢弃）。
6. 刷新页面后已生成的笔记还在（IndexedDB）。
7. 导出 Markdown 含：标题、链接、时长、字幕来源与可信度、带时间戳要点、未观看区段说明。

## 17. 待验证 / 风险

## v0.1.2 实施记录（2026-11-13）：第一次接真模型，改掉校验层的误杀

### 模型侧（deepseek-flash，用户提供的 key）
- Base `https://api.deepseek.com/v1`，可用模型只有 `deepseek-flash`（context 1,048,576，effort low/high/max，默认 high）与 `deepseek-v4-pro`。
- 默认带 `reasoning_content`：`max_tokens=700` 时 3 块 `content` 全为空（输出 token 全烧在 reasoning 上）；`max_tokens=2500` 时 reasoning 吃满、JSON 被截断。`reasoning_effort: "low"` 与 `effort: "low"` 都无效。
- 唯一有效解法：请求体加 `thinking: { type: "disabled" }` ⇒ reasoning 消失、882ms 返回。已写进 `src/background.js`，仅当 apiBase 含 `deepseek` 时自动加（避免 OpenAI 等因未知参数报错）；默认 `maxTokens` 700 → 1000。
- 实测（2132 句真实字幕，6 个连续块）：96~184 ms/块，输入 499~633 token，输出 250~492 token。

### 校验层的两处改设计（真模型暴露的）
- **时间戳不再采信模型**：`validatePoint` 原先要求 `|start - min(sids.from)| ≤ 0.5s`、`|end - max(sids.to)| ≤ 0.5s`；模型只写近似值（68.9/75.7 vs 68.86/76.6），6/8 条要点因此被误杀。改为**时间一律由 sentence_ids 的 from/to 推导**。
- **引文由字幕原文生成**：模型跨句引用常轻微改写（「只要任何低等生物靠近迷雾后……会瞬间被抓走」vs 原文「…靠近迷雾，就会…」），子串校验必然失败。改为：模型抄对（每段「……」都是所选句子的原文子串）就采信它更简洁的写法，否则用所选句子的原文拼接。
- 护栏：模型给的引文与所选句子**基本对不上**（二字片段命中 <50%）时整条丢弃，防「随机挑句子 + 另编一句原话」。判别函数 `bigramCoverage(claimedNorm, canonNorm)`。
- 结果：同一批 6 块，改前 12 条要点活 4 条（33%），改后 23 条活 22 条（96%）。

- 目标元素：`.video-container-v1`（找不到时退回 `#mirror-vdcon`）。

## v0.2.0 实施记录（2026-11-13）：只总结真正看过的区间

### 为什么改
v0.1.x 的队列条件是「块末 ≤ 当前播放时间」，于是把进度条拖到 1:10 时，中间 100 多块会被一次性入队——既烧钱，也违背「不剧透」这条产品原则（没看过的段落不该先替你下结论）。演示视频里一条拖拽就产生了 ¥0.15 的无关花销。

### 落地方式
- **覆盖区间**（`state.covered`）：只有「连续播放」才累计——相邻两次 timeupdate 的 `t - prev` 必须在 (0, 3] 秒内，否则视为跳转，不记覆盖。区间合并后存 `{a,b}` 数组。
- **80% 规则**：块「看过」= 整段连续覆盖到块尾 **或** 累计播放时长 ≥ 块长 × 0.8。后者是必须的：用户从块中间拖进来时起点永远覆盖不到，只判「覆盖到块尾」会让那一块永远不出笔记（真机复现：从 1:03 接着播 3 分钟，一块都没记）。
- **由块推导渲染**：`renderStream()` 每次整块重建——有 `noteIndex` 的输出笔记，未覆盖的相邻块合并成一条虚线占位条（`未观看 6:48–57:02 · 88 段` + 「总结这段」「去看这段」），已覆盖但还没出笔记的计入末尾「正在整理 N 段…」。整块重建换来的是「顺序永远对」：补总结出来的笔记是后追加的，`state.notes` 的顺序不等于时间顺序，所以**大纲必须按 start 排序**（`sortedNotes()`），否则补完的块会跑到大纲末尾。
- **两个按钮**：`forceBlocks(indexes)` 把这些块标成 covered+queued 并入队（花钱，按块数估 token 写在 title 里）；`seekTo(from)` 让用户自己去看。
- **滚动不抢**：`state.follow`，用户把笔记流往上滚（离底 >60px）就锁定并显示「回到最新 ↓」，点它回底部并恢复跟随。这是同类产品最常犯的错（新内容硬拉回底部）。
- **冷启动恢复**：`hydrateNotes()` 从 IndexedDB 的 `bvid:cid` 取上次的 `{notes,tokens}`，用 `linkNotes()` 按 start 挂回块上，token 计数也一起恢复（`addCost(0)` 会早退，所以直接写 DOM 文本）。
- 调试钩子：`window.__bnState = state`。扩展里内容脚本跑在隔离世界，页面读不到；但 `test/preview.html` 是普通 `<script>` 注入，可以直接在控制台/CDP 里看内部状态——这一轮的每个断言都是这么拿的。

### 验证
- `test/preview.html` 必须同步改：原来的「每 300ms 前进 5 秒」正好会被新规则判成跳转，一条笔记都不会出。改成每 300ms 前进 2 秒，并暴露 `pvSeek / pvPause / pvResume / pvNow`，句子扩到 60 句（300 秒 / 6 块）。
- 预览页实测：连续播放 → 块看完出笔记；`pvSeek(200)` → 中间出现「正在看 1:40–4:59」；点「总结这段」→ 4 块补齐、占位条消失、token 1.4k → 2.4k；点「去看这段」→ `currentTime` 回到区间开头；手动上滚 → follow=false + 按钮出现，5 秒内不被拉回，点按钮 → 回底且 follow=true。
- 真机（Edge 157 + deepseek-flash，BV1GyZYYNErW）：恢复 19 条笔记 + 2 条占位条；点 4 段那条「总结这段」→ 22 → 26 条、18.7k → 25.0k token（≈¥0.006）；从中间拖进未看区间继续播 → 80% 规则生效，1:05:02 / 1:05:19 两块出笔记，占位条被切成两段。截图 `dist/v020-gap.png`。
- 单元测试仍全绿：gate 29 / pipeline 11 / realdata 40。

### 仍然没做
- 走神补课（切走标签页 / 暂停的检测与横幅）、画面 OCR、抽样 ASR 内容校验。

## v0.3.1 实施记录（2026-11-13）：走神补课的真机 bug

真机（Edge 157.0.4341.46 + deepseek-flash + BV1GyZYYNErW）第一轮跑出来的现象：切走 95 秒回来，span 被记成 a === b（离开区间长度 0），横幅文案「这段还没记」；暂停 125 秒那条正常。

三个原因，都是同一个根：**B站 会在切回标签页的瞬间临时插入第二个 `<video>`**（paused、currentTime = 0），而代码一直用 `document.querySelector('video')` 取「当前 video」。
1. `getVideo()` 抓到临时元素 → `v.currentTime = 0`，`Math.max(hiddenFrom, 0)` 还是 hiddenFrom → span 塌成一点；覆盖区间也被切断（332.03 → 333.35 的缝就是这么来的，`lastTick` 被重置）。
2. `notesInSpan(a,b)` 只比笔记起点是否落在区间里：笔记 22–68 秒、离开区间 31–31 秒时明明覆盖了却判「没记」。
3. 离开期间视频继续播，但 `state.lastTime` 比临时元素的 currentTime 可靠。

修法：
- `videoScore(v)` 按「可见面积 + 时长 + 是否在播 + readyState + 是否 bpx-player」打分，`getVideo()` 在多元素时取最高分；面积权重最大，悬停预览那种小窗不会抢走正片。
- `notesInSpan` 改成**区间重叠**判据（`n.start <= hi && n.end >= lo`），不再只看起点。
- 回来时 `to = Math.max(hiddenFrom, state.lastTime, v.currentTime)`。
- `onVisibility` / pause / play 一律优先用当前绑定的那个 video（`videoBound`，且 `isConnected`）。
- 加了 `window.__bnAwayDebug`（最近 40 条现场：每个 video 的时间/暂停/宽高/时长 + 当时 lastTime），真机排查这类「哪个 video 才是正片」的问题时直接读它。

修后真机结果：span 960.8 → 1056.8（96 秒）；横幅「你离开了 1:36 · 这段记了 3 段」；3 条笔记带「你当时不在页面上」；补课视图 3 行一句话级；暂停 125 秒只出小挂件「补课 · 17:43」。单测 gate 29 / pipeline 11 / realdata 40 全绿。
## v0.4.0 实施记录（2026-11-13）：画面文字（本地 OCR）

### 为什么做
知识类视频里画面承载的是主线而不是补充（PPT、板书、代码、公式）。抽样估计 90% 的信息型画面承载的是**文字**，所以不需要 VLM——本地 OCR 就够，而且 OCR 出的字天然满足「可核对」。

### 选型（实测淘汰了两个）
- tesseract.js（chi_sim_best）：1080p 课件帧上正文识别成「在三角形 4BC 中，已知 w，D，4」，数学式全乱，还混入大量图线噪声行 ⇒ 淘汰。
- 云端 OCR：把画面传给第三方，与「不读你登录凭证、不做中间服务器」的隐私立场冲突，且要钱 ⇒ 不做。
- **PP-OCRv6 tiny + onnxruntime-web（wasm）**：npm 包 ppu-paddle-ocr@6.7.1，模型与 wasm 全部 vendor 进扩展（vendor/ocr/，约 29MB）。1080p 帧：init 270ms、识别 1.3~1.5 秒；同一帧重复识别走缓存 45ms。CDN 直连（esm.sh / jsdelivr +esm）在国内不通，所以用 esbuild 预先打成 IIFE bundle（635KB）。

### 设计（写进代码的约束）
- **只有「连续稳住约 2.4 秒」的帧才截**（40x24 灰度指纹，两拍差异 < 3.5 算稳定）。画面一直在动的游戏/影视基本不会被截——这不是缺陷，是「截了也是糊的/没信息」。
- **同一张画面不重复识别**：与上一张已截帧的指纹差异 < 4 就跳过；OCR 文字再做一层文本相似度（bigram Jaccard ≥ 0.9 视为重复）。一块最多挂 2 条、每条最多 600 字。
- **指代词强制取帧**：字幕里出现「这个图 / 这里 / 这个公式 / 这个结论 …」时，在调模型前 `force()` 立刻截一帧并最多等 2.2 秒——这是最值钱的帧（讲师说「你看这里」的时候画面就是答案）。
- **OCR 文字绝不进 quote**：`promptFor` 里明确写「画面文字是 OCR 可能有错字」、「quote 必须来自字幕原句、绝不写画面文字」、「字幕与画面冲突以字幕为准」；校验层的实体检查（数字/英文/书名号）把 OCR 文本并入可查范围，所以 OCR 能给「人话解释」背书，但不能给编造的引文背书（`test/visual.test.mjs` 第 9 条就是专门测这个）。
- 分辨率下限 720p：360p 中文正文只有 8~10 像素高，OCR 认不出来，`MIN_HEIGHT: 720` 低于此只提示一次「画面文字已跳过」。
- 没有字幕/没有块时不取帧（`shouldRun()`），省掉无意义的 JPEG 编码；帧用 canvas `drawImage(video)` 只拿解码像素，所以弹幕、播放器 UI、右侧推荐都不会进图（对比：tabCapture 截屏永远是脏图，已淘汰）。

### 架构
- 截帧在内容脚本（有 DOM 与 video）；OCR 在 **offscreen 文档**（MV3 service worker 里没有 DOM/canvas 可用，也不能跑 29MB 的 wasm 初始化）。offscreen 用 `BLOBS` reason 创建，单例懒加载。
- 通信：content → background（`{type:"ocr", dataUrl}`）→ offscreen（`{target:"offscreen", type:"ocr"}`）；结果按块挂到 `block.visual`，笔记生成时镜像到 `note.visual`。

### 真机踩到的三个坑（都写进代码注释了）
1. **offscreen 文档里 `img.decode()` 永不 resolve**（20 秒超时）——offscreen 文档不参与渲染。现象是「帧截到了、OCR 永远 0」，最迷惑。改用 `base64 → Uint8Array → Blob → createImageBitmap → canvas`。
2. **`recognize()` 返回的 lines 是嵌套数组**（`lines[0] = [{text, box, confidence}]`，即「每张图一个数组」），直接读 `l.box.y` 会抛 `Cannot read properties of undefined (reading y)`，面板显示「画面文字识别失败」。加 `flattenLines()` 拍平。
3. **扩展重载会留下「文档在、监听器已死」的僵尸 offscreen**：`hasDocument()` 为 true 也没有用。`ensureOffscreen()` 建好后先发 `ocr-warmup` 探活 5 秒，没回应就 `closeDocument()` 重建。另外 recognizes 全部包了 `withTimeout`（init 30s / 解码 10s / 识别 20s）——OCR 的串行队列一旦被一条永久 pending 的 Promise 占住，之后所有请求都会排队等死。

### 验证
- 自然取帧：BV1GXZAY7EWe（课件，5051 秒）静止画面 10 秒内 captured 1→3；BV1GyZYYNErW（游戏实况）连续 80 秒 captured=0（符合设计）。
- 端到端（真扩展 + deepseek-flash + BV1twZ4YzEmv「深度|| 香火之战」43 分钟）：自然取帧 2 张（661.3s、686.5s），OCR 出「渤海小吏LilLil / 第四十四回 / 法身元运逢车力，心正妖邪度脊关 …」，挂到 653.5–698.9 那一块；笔记标题「画面文字 · 11:01 / 11:26」，点开是 OCR 原文；4 条引文仍是字幕逐字句。截图 `dist/v040-note.png`。
- 强制取帧（BV1GyZYYNErW seek 300）：frames=1、ocr=1、visual 挂到 290.06–327.56，文字「这座基岩山据说是远古时期的陨石」，面板出现「画面文字 · 5:02」，0 条 console 异常。
- 单测：`test/visual.test.mjs` 9 passed（prompt 里带 OCR、禁止画面文字进 quote、只有画面才有的数字有/无视觉的差别、画面文字不能为编造引文背书）；gate 29 / pipeline 11 / realdata 40 仍全绿。

## v0.5.0 实施记录（2026-11-13）：音画对齐（L2-A）与它撞上的墙

### 为什么先做这一层
L2（字幕 ↔ 音频忠实性）原本分两件事：①时间轴对不对（字幕早/晚/漂移）②文字对不对（是不是逐字稿）。①不需要 ASR，只要音量包络；②要 ASR。本机拿不到 ASR 模型（huggingface.co 与 github.com 都不通，只有 media.githubusercontent.com 慢速可用），所以先做①，把②留成待拍板的路线。

### 实现（`src/align.js` 纯函数 + `src/audio.js` 采样）
- 语义：δ = 「把字幕时间整体平移多少才能对上音频里说话的位置」。δ>0 ⇒ 音频晚于字幕 ⇒ 文案「字幕比音频早」。`shiftFor(res, t)` 给出映射，`describe(res)` 给出人话。
- `toBuckets`：样本 `{t, rms}` → 按 `k=round(t/0.2)` 分桶取最大 RMS。0.2 秒是精度与噪声的折中。
- `scoreDelta`：每个桶算出 `p = b.t - delta`，二分查它是否落在合并后的字幕区间里；`score = cover - 0.4 * (1 - 静音落在区间外的比例)`。
- `scan`：δ ∈ [-10, +10] 步长 0.1；**同分时优先选离 ref 近的峰**（字幕句长/停顿近似周期时得分曲线会出现多个等高锋，ref 默认 0，分段时传上一段 δ）。
- `analyze` 流程：无样本→`no-audio`；无字幕→`no-cues`；桶裁剪到 [首句-12, 末句+12]；p20/p90 分位，p90<0.008→`no-audio`；阈值 `thr = p20 + 0.25*(p90-p20)`；语音秒数 < 20 →`too-little`；**分段（3 段）必须在 MIN_SCORE 判死之前做**（漂移时全局得分天然偏低，实测 0.49，先判死会漏报）；加权最小二乘 `δ = a + b·t`；漂移需四条同时成立（≥3 段、平均段得分 ≥0.6、spread ≥1.0、最大残差 ≤1.5、|b|>0.0005、best.score ≥0.45）→ `drift`；否则残差 >1.5 且得分 <0.75 → `unreliable`；再否则得分 <0.55 → `unreliable`；再否则 |δ|<0.5 → `aligned`，其余 `offset`。
- `src/audio.js`：懒建 AudioContext + AnalyserNode（fftSize 2048、smoothing 0），**必须 `analyser.connect(ctx.destination)`**——这套 API 唯一硬坑，忘了用户会突然听不到声音（已写进文件头注释）。`createMediaElementSource` 每个元素只能建一次，用 WeakMap 缓存。ctx 非 running 时记 `suspended` 并跳过采样；视频暂停/结束/`shouldRun` 假时不采；`rms > 1e-4` 计 nonzero。
- 界面：状态条下方一行小字（`.atag`），只在 `aligned / offset / drift / unreliable` 时显示；偏移量变化 >0.2 秒才重绘笔记流与大纲，避免每 15 秒抖一次。时间校正只作用于显示与跳转（`audT`），**不写回已存笔记**；走神区间与画面帧时间不套 shift（它们是视频真实时间）。

### 真机撞上的墙（这是这一版最重要的产出）
1. 第一次真机跑出来的是**假结论**：`aligned · 偏差 0.0s · score 0.6`。
2. 原因是 B站 AI 字幕时间轴几乎连续：BV1twZ4YzEmv（1390 句）合并区间后只有 22 段、覆盖 **97.5%**；BV1GyZYYNErW（2132 句）只有 11 段、覆盖 **98.9%**。「语音落在字幕区间内」对任何 δ 都成立 ⇒ cover 恒等于 1、得分曲线全平，peak 只是 tie-break 取到的 ref=0。分数 0.6 也正好等于 `1 - 0.4×1`，说明「静音落在区间外」的比例是 0 —— 因为没有区间外。
3. 试过换判据：用「能量上升沿」与「字幕起点」对齐（桶差分半波整流 + 局部峰，win=0.25s）。命中率 δ=0 → 0.804、δ=-0.2 → 0.902、δ=1 → 0.824，随机基线约 0.53：**有信号，但峰间差距太小，不足以支持「字幕晚了 1 秒」这种结论**。放弃。
4. 结论：在「句句相连」的字幕上，时间轴校正这一层是**信息不足**，不是算法不够好。所以改成显式认输——先算覆盖率，`> 90%` 直接返回 `no-gaps`，界面什么都不说。

### 状态与默认值
- 默认**关闭**（`bn.audioEnabled` 默认 false）：一是 B站 AI 字幕判不出来，二是接管音频输出本身有风险（切走标签页时浏览器可能挂起 AudioContext，导致「走神期间继续记笔记」时没声音）。设置页文案写明了这两点。
- 打开后若判出偏移/漂移，界面时间按音频校正；判不出或不可靠时保持静默，不显示任何对齐信息。

### 验证
- 单测 `test/align.test.mjs` **33 passed**：合成不规则字幕（句长 1.2~3.6s、停顿 0.3~1.9s）下，恒定偏移 1.3 / -2.0 / 4.5 秒能估到 ±0.3；漂移 0.008/s（600 秒漂 4.8 秒）能判出 drift 并给出斜率；no-audio / no-cues / too-little / 纯噪声都不得误判成 aligned；新增 5 条针对 `no-gaps`（含真机素材 `test/fixtures/audio-real.json`：1390 句 + 426 桶 → no-gaps）。
- 测试数据的教训：最初用「每 3 秒一句」的周期数据，δ=-2 会被估成 -5、无偏移判成 unreliable——**周期性数据本身有歧义**，任何算法都分不出来。必须用不规则句长/停顿。
- 真机（Edge 157，端口 9333，BV1twZ4YzEmv）：开 `__bnAudio.enabled(true)` 后 20 秒采满 360 桶、ctx running、attached、nonzero 718、无静音；30 秒时 `too-little (19.4s)`，50 秒起稳定 `no-gaps / cueCoverage 1 / gaps 21`，界面保持安静；切到 about:blank 6 秒后 ctx 仍 running、采样继续。截图 `dist/v050-audio.png`。
- 真机操作坑：不给真实鼠标手势时 Edge 把带声音的播放拦成静音（实测 nonzero 只有 35/350、p90=0，被判 `no-audio`）；必须先用 `Input.dispatchMouseEvent` 点一次页面再 `play()`。

### 仍然没做
- L2-B 抽样 ASR 内容校验（字幕是不是逐字稿、有没有转写错字）：需要 ASR 模型或云端 ASR key，**等用户拍板**。
- 在有人工字幕的视频上验证偏移/漂移两条分支（手里 20 条样本全是 AI 字幕，目前只有合成数据支撑）。
- 把校正后的时间写进已存笔记（现在只影响显示与跳转）。

## v0.5.1 实施记录（2026-11-13）：多 P

### 为什么先做这件
L2-B 拍板「不做」之后，候选队列是：多 P → 导出带画面文字 → 长视频性能。多 P 排第一，因为它是**最容易被日常撞到**的：B站 课程、课程合集、番剧式连载全是多 P，原来在 P2 上看到一半点 P1 就得刷新页面，刷新后笔记虽然能从 IndexedDB 恢复，但闸门要重跑（几秒到十几秒）、播放头复位、浮层闪一下。

### 认「现在是第几 P」的三级信号
优先级从高到低，能拿到前者就不看后者：

1. **播放器高亮项**（最可靠）：`.video-pod__item.active` 的 `dataset.key` 就是这一 P 的 **cid**（实测 "1519832023"）。备用选择器 `.video-pod__item--active`、`#multi_page .list-box li.on`。拿到 cid 后直接和 view 接口返回的 `pages[{page,cid,part,duration}]` 对上，连请求都不用多发。
2. **URL 的 `?p=N`**：B站 换 P 会改 URL，所以 href 变化顺带驱动重跑。
3. **时长自校正**（兜底，只在前两级都给不出答案时用）：当前认定的 P 时长与 `video.duration` 差 >5%，而 `pageList` 里另一个 P 的时长差 ≤2% ⇒ 认定切到了那一 P。两个条件都要满足，否则宁可不动（很多视频多个 P 长度相近，乱猜比不猜更糟）。每个 cid 只试一次，结果记在 `healed`。

为什么不能只靠 view 接口的 `d.cid`：**它永远指向默认 P**（通常 P1）。原代码就是这么写的，切到 P2 时会拿到 P1 的字幕与时长，闸门用 P1 的时长去卡 P2 的字幕，必然判 truncated。

### 换了什么
- `gate.resolveVideo(bvid, wantP)` 返回 `{pageList, page, part, pages}`；字幕与时长都按选中的 P 取，IndexedDB 键仍是 `bvid:cid`，所以每个 P 天然是独立的一份笔记。
- 状态条 dot 后加一个小标记「P3/70」（只有多 P 才显示，title 写「第 N P · 分P名（共 M P）」）；导出 Markdown 的 frontmatter 多 `page: N/M` 与 `part`，文件名与标题带 `-P{n}`，时间链接补 `?p=N`。
- 换 P 不刷新页面：`watchPage()` 每 2 秒巡检高亮项的 cid，变了就 `boot(false, hit.page)`；`boot` 用「bvid + p 都相同」做早退，所以同一 P 的杂七杂八 URL 变化不会重跑闸门。

### 这一轮抓出的两个真 bug（都是「只有切 P 才会撞到」的）
1. **界面永远停在「检查字幕 5/5」**。B站 页面加载后会把 URL 改写成带 `vd_source`/`spm_id_from` 的形式，这会触发一次 `boot(false)`；那次在早退判断里 `return` 了，但 `const seq = ++bootSeq;` 写在早退**之前**——令牌已经被换掉，正在跑闸门的那一次回来发现 `seq !== bootSeq`，按设计静默退出，状态文字就永远停在最后一次进度上。修法：早退通过之后才自增令牌。教训是**「早退」和「换令牌」不能写在同一个前缀里**，否则每次无害的重入都会废掉正在跑的那次。
2. **`Cannot read properties of undefined (reading 'start')` at `noteEl`**。切回某个 P 时用的是快照里的 `blocks` **对象本身**，上面还留着上一轮的 `noteIndex`；`linkNotes` 看到 `noteIndex` 非空就跳过重挂 ⇒ 索引指向上一个 P 的 `state.notes`，渲染时取到 undefined。修法三处：`linkNotes` 先整体清空 `noteIndex` 再按 `start` 就近（±0.5 秒）重挂；`renderStream` 里命中不到笔记就把 `noteIndex` 置回 null 按「还没出笔记」渲染；`stash()` 在 `sentences` 为空时干脆不存快照（否则会「恢复」出一个空会话，之后再也不去取字幕）。

### 验证（Edge 157 真扩展 + deepseek-flash，BV1rH4y1N7BW 共 70 P）
- 冷启动 `?p=2`（cid 1519832023，2845 秒，2.2.02矩阵消元）：状态条「P2/70」，闸门 3 次取样拿到 stable（ok@0.996 / truncated@0.127 / ok@0.996），切成 **96 块**，播 30 秒出 1 条真笔记。
- 真点分 P 列表切 P1（cid 1519829483，2378 秒）：**页面没刷新**（页面里打的标记还在），重跑闸门（truncated@0.13 / empty-url / ok@0.998 / truncated@0.722 / ok@0.998 → stable），**74 块**，笔记数归 0，标记变「P1/70」。
- 切回 P2：笔记 2 条原样恢复，状态条「已恢复」。
- 顺带确认：同一个 P 反复取字幕也会拿到不同文件（P2 那三次里有一次 truncated@0.127），所以「取样多次」这条规则不是给跨视频用的，是给每一次取字幕用的。
- 脚本：`test/probe-pages.mjs`（缓存路径 + 来回切 P）、`test/probe-pages-fresh.mjs`（清库冷启动 + 两个 P 各自跑闸门）；单测 `test/pages.test.mjs` 覆盖 pageList 选取、cid 优先于 ?p=、时长自校正的两个门槛、以及片段结束为空时不存快照。截图 `dist/v051-p2.png` / `v051-switch.png` / `v051-p1.png`。

### 边界（写进 README 的已知问题）
- 认 P 依赖 B站 播放器的 DOM（`.video-pod__item[data-key]`）。这个结构哪天改了，就会退回 `?p=` 和时长自校正，可能认错 P——但认错 P 的表现是「字幕对不上、闸门判 truncated」，不会静默出错笔记。
- **合集不是分 P**。同一 UP 的一串独立视频（`bilibili.com/video/BVxxx?p=1` 之外的「合集/播放列表」）没有 `.video-pod__item`，切换靠时长自校正，可能认不出来；那种页面上的正确做法是自己刷新。
- 某个 P 没字幕时，在那一 P 上就是「没有字幕」，**不会回退去总结别的 P**（宁可明说不可用，也不给一份不属于这一 P 的笔记）。
- 直播回放、番剧、课程（cheese）不做。

## v0.5.2 实施记录（2026-11-13）：导出 Markdown 带上画面文字

### 为什么
笔记是资产，导出是它离开这个扩展的唯一出口。v0.4.0 有了画面文字之后，导出里却不带——一份 PPT 课的笔记导出后就丢了板书那半截，等于把最有价值的旁证扔了。

### 怎么放（格式选择）
原则和界面一致：**必须一眼看出这不是原话**。所以：

- 单独一段，标题写死「**画面文字（OCR，机器识别，可能有错字，不是原话）**」；
- 每张画面一行时间链接 `[11:01](…&t=661)`，后面跟一个三反引号代码块放 OCR 原文——代码块是为了**保留换行**（PPT 是一行一行读出来的，挤成一整段就没法扫），同时视觉上明确是「机器读到的文本块」，不会和下面的引用块（`>`）混淆；
- frontmatter 里多一行 `visual_frames: N`（为 0 时不写），方便以后按「有没有画面信息」筛笔记；
- 顺序：先原话要点、再「如果只记一件事」、最后画面文字。原话是主，画面是辅。

### 顺手修掉的两个问题
1. **多 P 的时间链接是坏的**：v0.5.1 加了 `pageUrl()`（多 P 时带 `?p=N`），但时间链接还在裸拼 `+ '?t='`，导出成 `...?p=2?t=22`——点开落在视频首页，不是那一秒。改成 `jumpUrl(t)`：已有 `?` 就用 `&`。只影响导出，界面上点时间是直接 seek，不受影响。
2. **导出顺序没按时间**：补总结补出来的笔记是 `state.notes` 后追加的，按数组顺序导出会排到文档最后。改走 `sortedNotes()`（大纲早就是这个原因才排序的，导出漏了）。

### 验证

## v0.5.3 实施记录（2026-11-13）：长视频稳定与性能（精度不变）

用户拍板：**「暂时还是要求精度」**（m02975）⇒ 第 3 件「长视频性能与成本」里，
凡是拿精度换速度的都不做：**不做倍速总结**（少喂字幕，引文会缺）、**不做多路并发**。

### 为什么不做并发（这是设计，不是偷懒）
每块的 prompt 都带着上一块产出的 `one_thing`（「如果只记一件事」），用来保持笔记的连贯。
这条链天生是串行的：第 N 块必须等第 N-1 块的一句话。
两路并发只有两种实现方式——(a) 第 N+1 块不等，直接空着 prev（连贯性掉一档）；
(b) 等 prev 到了再发（那就还是串行，只是多了一个在途）。既然用户要精度，选不做。

### 那还剩什么是「不损精度」的
1. **限流退避重试**（真实损失最大的一项：被 429 打断时，旧代码直接抛错、这一块永远不出笔记）。
   `RETRY = { attempts: 3, baseMs: 2000, rateMs: 5000 }`，可重试错误码 = rate-limit / network / timeout / http(5xx)；
   重试期间状态条写「排队中 · 等 5s（还有 12 段）」，不静默卡住。
2. **失败不再吞块**：重试用尽时把块 `unshift` 回队首并置 `state.queueHold = true`，
   队列停下来，面板底部出现「继续整理」按钮；不点就不会被 timeupdate 反复自动重试（那会在后台一直发失败请求）。
   `forceBlocks()` / `boot()` / `restore()` 都会清掉 hold。
3. **渲染与落盘节流**：`scheduleRender()`（120ms 合并）+ `save()` 改成 800ms 防抖写 IndexedDB，
   队列跑空时强制补一帧、补写一次；`pagehide` / `visibilitychange=hidden` 立刻 `flushSave()`。
   120 块时旧代码是「每出一块就整体重排 DOM + 整份序列化写库」，长视频上是 O(n²) 的活。
4. **队列进度可见**：`整理 mm:ss–mm:ss · 还有 N 段`、`排队中 · 等 Ns（还有 N 段）`。
5. 顺手修掉一个真 bug：`boot()` 清空 notes 之前没有 flush 防抖中的那次写，
   切视频/URL 被 B站 改写重跑 boot 时可能丢掉最后一两块笔记（真机复现过 noteIndex=0 但 notes 为空）。修法：`boot` 里 `stash()` 之后立刻 `flushSave()`。

### 验证（2026-11-13）
- 预览页（真 content.js + 假模型）：注入一次 429 → 状态条「排队中 · 等 5s」→ 5s 后重试成功、笔记照常出。
- 预览页：注入 401 → 队列停在 5 段、hold=true、6 秒后调用次数不增长；修好后点「继续整理」→ 5 段补齐（笔记 1 → 6）。
- 真机（Edge 157 / 9333 / 真 deepseek-flash）：BV1w6ZEYrEsb 从 0 播到 60 秒，30 秒时状态条「整理 0:00–0:43 …」、
  36 秒出第 1 条笔记、DOM 1 条、无 JS 异常；BV1GyZYYNErW 冷启动恢复到 5 条、播到 4:50 补齐第 6 条。

### 仍然没做

## v0.5.4 实施记录（2026-11-13）：字幕是不是人话（可读性标注）

### 为什么做
用户第一次拿到真实使用结果，报的问题不是「不准」而是「完全看不懂」：笔记里出现「讲者说明下一步动作，并讨论左右手与 matlab 的操作位置」，引文是「我可能需要被马特离开一会儿，然后那样做」。诊断是**外语视频的机翻字幕**：句子本身不通，而我们的规则（引文逐字、讲解不得新增事实）只能把破句子再解释一遍。闸门之前只查时长 / 结构 / 取样稳定，机翻轨和正常转写长得一模一样，状态条都写「B站 AI 字幕」。

### 第一版规则与它撞上的误报
第一版用三条证据的任意组合判 machine：音译名命中 ≥2 句、拉丁字母句占比、`被[1~4字](离开|做|说|…)` 的被动结构。在用户截图那六句上是 machine，但在 2132 句正常中文的《我的世界克苏鲁全集》上也报 machine —— 误报来源是「史蒂夫」出现 7 次（游戏角色名）加上 7 条完全正常的被动句（被叫做 / 被安放在 / 被派遣去 / 被冰封起来）。结论：**「被+施事+及物动词」在中文里完全正常，不能当独立证据**；专名（角色名、课件人名）单独出现也不能说明机翻。

### 最终规则（宁可漏报）
`src/gate.js` 的 `readability(sentences, opts)`：
- 唯一硬证据 `oddNamePassive`：`被 + 音译人名 + 动词`（正则由 `NAME_WORDS` 现拼，所以「被马特离开」命中，「被安放」不命中）。命中 ≥1 直接判 `machine`。
- 次级证据：`nameSents >= 2 && latinRatio >= 0.12`（音译名 + 夹英文字母），或 `latinRatio >= 0.3 && youPer100 >= 3`（满屏「你应该/让我们」+ 术语全英文）。
- `suspect`：`latinRatio >= 0.12 && (nameSents >= 2 || youPer100 >= 1)`，或 `youPer100 >= 3`。
- 少于 20 句返回 `unknown`（不下结论）。
- 单字名（雷/乔）与角色名（史蒂夫）都从「机翻证据」里退出：它们只能进 `flags` 给人看，不能单独定案。

### 界面与降级
- 判定写进状态条（`· 疑似机翻`）与面板提示条：machine 红字「字幕疑似机器翻译（原因），笔记可能不通顺；对照原话看。」；suspect 灰字「字幕可能有翻译痕迹，笔记仅供参考。」。
- `machine` 时每块要点上限 4 → 2，讲解层只做最小改写、不通就直说「这句字幕不通顺」；system prompt 永久加一条：不确定的专名/缩写（如 matlab）必须说「提到了 X，但不确定指什么」，**不许编定义**。
- 成本：本地判 clean 不调模型；只有 machine/suspect 才花一次约 300 token 的复核（模型说不是机翻就把 machine 降成 suspect）。结论连同字幕一起写进 IndexedDB，重载不重复花钱。

### 验证（2026-11-13）
- 单测：用户截图六句 → `machine`（nameSents=2, oddNamePassive=2）；40 句正常中文 → `clean`；只提一个人名 → 不是 machine；24 句「史蒂夫 + 被安放」→ `clean`（把这次误报锁进测试）；真实 fixture《我的世界》2132 句 → `clean`。gate 40 passed。
- 真机 UI（`test/verify-readability.mjs`，截图 `dist/v054-machine.png`）：正常中文字幕提示条隐藏；`show('machine')` 后提示条红字 + 状态条「· 疑似机翻」；`show('suspect')` 后灰字。
- 用户路径验收（`test/accept.mjs`，真 Edge + 真扩展 + 真 deepseek-flash）16 / 16 通过：3 个不同分区视频各自「闸门 → 拖进度 → 出笔记 → 点时间跳转 → 导出」，一次切走 95 秒回来，一个无字幕视频明确显示「字幕不可用」，扩展自身 0 异常（B站 播放器 tracker 的 WebSocket 断连计入站点噪声）。

### 仍然没做
- 真实整段外语机翻视频的端到端样本（手里没有；用户没给那个 BV 号）。目前只有截图六句 + 正常中文回归两侧。

## v0.6.0 实施记录（2026-11-13）：画面字幕兜底（烧进画面的字幕）

### 为什么做
用户第一次实操就撞上《变态心理学 北京大学》：B站 接口返回 0 条字幕轨，面板只能说「字幕不可用」。而知识区里大量搬运课/纪录片/外语剪辑的字幕是**直接烧在画面里**的（无轨可查），这一类视频对「字幕优先」策略是黑洞。既然已经有本地 OCR（v0.4.0 画面文字），就能拿它读**画面底部那条字幕带**，把「带时间的句子」重新造出来，接进现有的切块/总结管线。

### 与 v0.4.0 画面文字的区别（两条通道，互不复用）
| | 画面文字（v0.4.0） | 画面字幕（v0.6.0） |
| --- | --- | --- |
| 目的 | PPT/板书作为理解旁证 | 造出**原话**（进引文） |
| 触发 | 自动（连续 2.4 秒稳定帧） | 用户点「用画面字幕试试」 |
| 采样 | 稳定帧，稀疏 | 每 0.6 秒一次，密集 |
| 裁切 | 整帧 | 只有底部字幕带（高度 58%~98.5%） |
| 结果去向 | 挂到块上，只进人话 | state.sentences → 切块 → 总结；笔记标「画面字幕（识别）」 |

### 关键设计
- **必须用户点**：每帧 OCR 约 1~1.5 秒、整片跑很吃 CPU，而且多数视频没有硬字幕；不做成默认自动。
- **分辨率闸**：videoHeight < 700 直接拒绝并说清原因（480p 中文正文只有十几像素高，实测 OCR 全是噪声：「相同不同一相同一不同一不清楚北京大字」）。这比「跑十分钟给一堆垃圾笔记」好。
- **行清洗**：纯标点/纯时间/水印词/单字符全是同一字的乱码行丢掉；**双语字幕只留中文行**（耶鲁公开课是中文一行、英文一行，两行都留会让每句话重复一遍意思）；整帧没有中文才留外文行。
- **台标水印挖除**：右下角 logo 文字会和字幕挤在同一行，OCR 认成 UniverSity / nIVerSIty / aleUniversity / e1Sity。按「与 university/bilibili/yale 的 bigram 相似度 ≥0.62（4 字词 ≥0.8）」+「英数混排碎屑」挖掉；正常术语（matlab / philosophy）不误杀。
- **cue 聚合**：往回拖忽略、文本相似（≥0.82，或 4 秒内 ≥0.5）算同一句、空帧隔 4 秒收尾、同一短文本持续 25 秒且 ≤16 字判台标。CUE_MERGE_SEC 从 2.5 提到 4.0 是因为采样间隔可能被 OCR 拖到 3 秒以上。
- **拼句与切块**：超长 cue 按标点/字数切（时间按字数比例分），再按 2.5 秒停顿/句末标点/36 字断句；攒够 4 句就 chunkSentences 入队（末尾一句还在长，先不切，否则半句被永久截断）。
- **自动停**：连续 60 次没认到字、或采满 900 帧，自动停并说明。
- **冷启动恢复**：闸门失败分支先 hydrateNotes()，有笔记就把它们合成 blocks、verdict 设 hardsub、状态条「画面字幕 · 上次的笔记」。重认一遍要整片重播，代价太大；要重认有「重新识别」按钮（会清空旧笔记）。
- **rejected 的状态文案**：原来 STATE_TEXT 没有 rejected 键 → 显示无信息量的「字幕不可用」。现在写「字幕取样不稳定」，提示说明「B站 这次给的字幕文件对不上这个视频（时长或内容不符），点再试一次重新取样，也可以试试画面字幕」。

## v0.7.0 实施记录（2026-11-13）：讲解层口语化 + 小节标题

### 为什么做
用户 m03142 的第二个抱怨是「总结的不知道什么东西，完全看不懂」。上一个版本先把「字幕随机给错」这个外来因素摘掉了（v0.6.1 投票），这一步处理我们自己的写法：旧 prompt 允许「讲者说明了 X」这种转述体，笔记本该回答「这段在解决什么问题、结论是什么、为什么」，却写成了一句语法正确但没信息量的旁白。术语也在硬拗（matlab 被解释成「一个操作或工具」）。

### 三条具体改法
- 开场换问法：每段的一句话（block_summary）必须用「它在解决什么问题 / 它回答了什么」的口吻，不许写「讲者说明了…」「这一部分介绍了…」。能用动词的地方不许名词化（写「把录音整理成清单」不写「对录音内容的整理」）。
- 给对照，不给形容词：prompt 里同时放一条反例和一条正例。反例「讲师深入阐述了协方差矩阵的统计学意义，揭示了变量间的协同变化规律。」标注为「不要这样写」，并点明三个毛病：拔高、名词堆砌、等于没说。正例「它只回答一个问题：两个东西是不是一起动。」——这是唯一能让模型听懂「人话」的手段（形容词它理解不了，示例它抄得会）。
- 术语守住不确定性：不确定的专名/缩写允许写「提到了 matlab，但不确定指什么」，绝对不许编定义。这条是硬规则，不在讲解层「自由发挥」的范围内。

### 小节标题（为什么每 8 段一次）
- 粒度：SEC.BLOCKS = 8（8 块约 3~6 分钟）。一条笔记一句话已经够细，但大纲要能「一眼看到讲了哪几件事」，全片一次总结会退化成漂亮的废话，所以按段聚。
- 只喂这 8 段的一句话，不喂全片摘要，也不给视频标题——否则模型会拿结论倒推，产生「后见之明式」的小节名（把后面才讲的东西写进前面的标题）。
- 输出只有 title（≤12 字）和 one_line（≤30 字）。标题要能当目录用，所以禁评价词、禁「本节讲/第一部分」这种零信息前缀。
- 只给最早还没做的那一组做（顺序推进，不并发），同组失败最多重试 3 次，避免一次抖动就把这一节的标题永久丢掉。

### 落地时撞到的两件事
- 前缀剥离的顺序坑：正则里 第一[部章节] 必须排在 第[一二三四五六七八九]部分 后面，否则「第一部分」先被「第一部」吃掉、剩个「分 存档」。
- 标题过长不能整节丢弃：第一版对 >18 字的标题直接判不合格，真机上模型给了 26 字 → 什么都不显示，看起来像功能没生效。改成「>28 字丢弃 / 18~28 字截到 18」+ 重试。

### 验证（2026-11-13）
- 单测新增 test/section.test.mjs 25 条；test/pipeline.test.mjs 的 prompt 长度上限从 900 放宽到 1200（加示例后实测 1048 字）。全套 9 个测试文件（gate 40 / pipeline 11 / realdata 40+0+20 / align 33 / pages 15 / visual 9 / hardsub 61 / vote 10 / section 25）全绿。
- 预览页（假模型，零成本）：seed 8 块后大纲出现「0:00–5:20 光反应的过程」，IndexedDB 里 sections 存成 ["光反应的过程|0-320"] 持久化正确。

## v0.7.2 实施记录（2026-11-14）：失败态说人话 + 70KB 轻量包

### 为什么改

两件都是「可用性」而不是「能力」：①失败时只有一句「出错了」类的话，用户不知道是自己操作错、网络问题，还是这个视频压根没有字幕；②完整包 11.6MB / 解压 31MB，其中 29MB 是本地 OCR 模型——但绝大多数知识区的视频 B站 有 AI 字幕，那 29MB 对他们是纯负担（下载慢、装的时候被吓到）。

### 失败态：五种以上分开说，每种两行

判据来自前一轮的真机：用户其实只想知道两件事——「是不是我做错了」和「我现在该点哪里」。所以每条都是「发生了什么（含归因）→ 你能做什么」，且归因明确写出来（B站 那边的问题 / 你的登录态 / 你的清晰度），不含糊其辞。
- STATE_TEXT 与 FAIL_HINT 拆开：状态条只放一句短标题（「字幕和视频对不上」），面板里才放整段解释。
- rejected 的文案特别写清「用了就会给你一份别的视频的笔记，所以没采用」——这是我们拒绝它的真实原因，用户有权知道，否则会以为是 bug。
- need-login 写成「登录（右上角头像）→ 刷新本页，就会自动重新检查」，不留「请登录」这种命令式空话。
- 排版从居中（text-align:center; opacity:.6）改成左对齐（.empty .et 加粗标题 + 正文 opacity:.78）：长句居中非常难读，而失败面板的正文恰恰是长句。

### 轻量包：不是「砍功能」，是「功能不存在时不给你入口」

- 打包不加第二份源码：test/zip.mjs 加 --lite，只把 vendor/ocr 从清单里滤掉（6 个文件、约 29MB），输出 bili-notes-v<ver>-lite.zip。
- 关键差别不是体积而是**入口**：轻量包里点「用画面字幕试试」只会得到一个报错，这比没有按钮更糟。所以启动时探一次 OCR 文件：content.js 的 probeOcr() → background 的 probeOcr 消息 → SW 里 fetch(chrome.runtime.getURL('vendor/ocr/models/ppocrv6_tiny_dict.txt'))，不在就把 OCR_OK 置 false，hardSupported() 直接返回 false，顶栏「画面字幕」按钮加 .hidden、失败面板不渲染「用画面字幕试试」。
- **踩到的坑（重要）**：最初让内容脚本自己 fetch chrome-extension:// 资源，**真机两个包都判成「没有 OCR」**——内容脚本的 fetch 用的是页面源，MV3 下要 web_accessible_resources 且受页面 CSP 约束，B站 页面会直接挡掉。改成让 service worker（扩展源）代探一次才恢复。这个 bug 在预览页看不出来（预览页没有 chrome 对象，走了「保持 OCR_OK 不动」的分支），只有真扩展能暴露。
- 探不到时（不是扩展环境，比如预览页/测试页）不动 OCR_OK：否则 preview-hard.html 这类页面会把「画面字幕」整块变没。

## v0.7.3 实施记录（2026-11-14）：工具栏图标——点一下就打开面板

### 为什么
用户原话（m07338）：**「一点都不省事，我需要它和其他插件一样，点一下图标就可以用」**。

之前 v0.7.2 及更早，扩展在 manifest 里**根本没有 `action` 字段**，所以它天生没有工具栏图标：唯一用法是打开视频页后等面板自己从右边滑出来。用户的 profile 里 Edge 还把「来自其他源」的扩展默认关着（黄条：此扩展不是来自任何已知来源），于是他的真实体验是「装了个东西，点了没反应，也不知道它到底在哪」。这不是配置问题，是入口缺失。

### 怎么改
- manifest 加 `action`（title「B站可核对笔记 · 点一下打开面板」+ 16/32/48/128 图标）与顶层 `icons`；额外要 `scripting` 权限和 `https://www.bilibili.com/*` 的 host 权限。

- 点击链路 `openPanelForTab(tab)`（background）：不是视频页 → 直接开 B站 首页标签（宁可多开一页，也不要「点了没反应」）；是视频页 → 先 `chrome.tabs.sendMessage({type:'bnOpenPanel'})`，失败说明这页是装扩展之前打开的、没有内容脚本，就 `chrome.scripting.executeScript` 补注入七个脚本再试一次；还不行就在图标上挂橙色「↻」角标（意思是这页要 F5）。
- content.js 端新增 `openPanelFromIcon()`：收起态自动展开 + 面板左边框闪一下（`flash` 类，1.1s）作为「是它开了」的确认；BVID 变了会重新 boot。这是 content.js 第一个 `chrome.runtime.onMessage` 监听器。
- `test/zip.mjs` 从 manifest 的 `icons` / `action.default_icon` 收图标——否则图标进了 manifest 却不进 zip，装到别人机器上就是空白图标。

### 验证（12/12，Edge 157 真扩展，`test/icon-click.mjs`）
扩展 0.7.3 载入（mdpphognlfhkeenfmpopbbgmpdhafpfp）／`manifest.action` 存在／`chrome.action.onClicked.hasListeners()` 为 true／标题正确／`__bnOpenPanel` 可调用／视频页面板挂载／前置点收起后 `wrap collapsed` 宽 52px／唤出返回 `{via:'panel',ok:true,bvid,collapsed:false,notes:26}`／唤出后展开且带 `flash`（宽 399px）／非视频页返回 `{code:'not-video',opened:...}` 并真开首页。截图 `dist/v073-icon-open.png`。

### 踩到的两个坑（写进脚本注释了）
1. **Edge 会继续跑旧版 service worker**：改完文件不 reload，SW 里还是旧代码，但版本号读的是新 manifest。症状是 `hasListeners()=false`、`self.__bnOpenPanel=undefined`，而 `fetch(chrome.runtime.getURL('src/background.js'))` 回来明显已是新代码。解法：在 SW 里 `chrome.runtime.reload()`，等 5 秒重新 attach。
2. **面板在 shadow root 里**：主世界 `document.getElementById('bn-root')` 能拿到宿主但 `querySelector('#btnFold')` 永远 null；而且 CDP 的 targetId 是字符串，`openPanelForTab` 要数字 `tab.id`——验收脚本必须用 `chrome.tabs.query` 取真实 Tab 对象。

- 图标角标只表达「这页要刷新」，没做点击后的失败详情。
- 非视频页固定开 B站 首页，没有按当前页面猜用户想看什么。

## v0.7.4 补充（2026-11-14）：开发者模式必须常开 + 绝不强杀浏览器（B站 登录态）

这节记录两件都不是「功能」的事：一条环境规则（关掉会坏）和一条操作纪律（违反了会丢用户的登录态）。用户原话（m07921）：**「不是没登陆，而是你每次装好像都会让我退出b站登录，我每次都要重新登录」**。

  - 对应进程命令行 `msedge.exe --no-startup-window /prefetch:5`（本次 PID 40212，12:43:19 启动），另有 crashpad-handler / gpu-process / network、storage utility / 2 个 renderer 作为它的子进程。
  - 设置位置：`edge://settings/system` →「启动增强」。关掉之后关窗口 = 真退出。
- 实测对照：窗口已全关（UIA 枚举 `Chrome_WidgetWin_1` 只剩别的几个 Chromium 应用），msedge 仍有 7 个进程；对这些进程的 5 个隐藏窗口（`crashpad_SessionEndWatcher` / `Chrome_WidgetWin_0` / `Base_PowerMessageWindow` / 2×`IME`）PostMessage(WM_CLOSE) 无效，进程数反而 7→8。

### 3. 硬杀浏览器 = 丢 B站 登录态（因果链）
1. 我用 `Get-Process msedge | Stop-Process -Force` 关浏览器；
2. `Default\Preferences` 里留下 `profile.exit_type = "Crashed"`（「上次是被硬杀的」的物证，本次实测仍是 Crashed）；
3. `Default\Network\Cookies`（557056 字节，SQLite）在 storage 进程里被**独占锁定**：运行中连读都读不出来（copy 直接 sharing violation）；
4. 硬杀发生在写事务中途时，最近一次 cookie 提交会回滚 ⇒ B站 的 SESSDATA 回到登录前的值 ⇒ 用户下次打开就是未登录。

### 4. 因此定下的硬规则（也写进了 `bili-notes/AGENTS.md`）
- **绝不** `Stop-Process -Force msedge`，也不 `taskkill /F`。
- 只允许 `CloseMainWindow()`，然后轮询进程自己退干净，最多等 60 秒；超时就**停手告诉用户**，由用户手动退。
- 动配置档（Preferences / Local Extension Settings）前必须 Edge 全关；关不干净就别改。
- 用户重登后立刻抓一份 `Cookies` + `Local State` + `Preferences` + `Local Extension Settings` 备份（`edge-safe.ps1 -Backup`），出事 `-Restore` 还原，别让用户重输账号。

### 5. 备份的边界（为什么 -Backup 一开始总是 exit=2）
`-Backup` 要求 Edge 真正退出：启动增强开着时窗口关掉进程也不退，Cookies 仍是独占锁，备份必然失败。所以正确顺序是：**先在 `edge://settings/system` 关掉启动增强 → 再关窗口 → 再 `-Backup`**。这是环境约束，不是脚本缺陷；脚本会明确报「Edge 还开着，Cookies 被独占锁定」而不是静默跳过。

### 6. 以后升级的正确姿势（不碰进程就不掉登录）
改源码 → `sync-my-edge.ps1`（robocopy 到已装载目录 `bili-notes-my/`，跳过 `dist`）→ `edge://extensions` 点「重新加载」→ 回视频页 F5。**全程不需要关浏览器**，也就没有掉登录的风险。注意只 sync 不「重新加载」的话，Edge 会继续跑旧 service worker，而版本号显示的是新的。

## 验收脚本修正（2026-11-14 下午）：两条「永远红」的断言

这两件事都**不是产品 bug**，是验收脚本自己的判据错了。它们让「用户路径验收」从 16/16 掉成 12/16、而且是稳定复现的红，很容易被误读成「扩展坏了」。

### 1. 无字幕断言从 v0.7.2 起永远是红的

- 旧判据：`const saysNo = (verdict === 'noSubs') || (s && /不可用|取样不稳定|暂时做不了/.test((s.status||'')+(s.note||'')));`
- 为什么红：v0.7.2 把 `STATE_TEXT.rejected` 的文案从兜底那句「字幕不可用」改成了具体人话**「字幕和视频对不上」**（`src/content.js:1715`），而正则只认「不可用 / 取样不稳定 / 暂时做不了」。无字幕样本 `BV1BtZJYBE4G` 在真机上一直落在 `rejected`，于是状态条写得再清楚也判红。历史证据：`dist/accept-v072.log` 第 16 行 FAIL（rejected + 字幕和视频对不上）、`dist/accept-run.log` 第 16 行 PASS（当时的兜底文案还是「字幕不可用」）。
- 新判据（`test/accept.mjs:187–192`）：verdict 命中**明确的失败结论**集合 `['noSubs','rejected','truncated','overflow','malformed','empty','emptyUrl','ambiguous','timeout']`，且状态条是一句 ≥4 字的人话；同时排除登录态（`need-login` 或文案里出现「请先登录/登录后/未登录」）——登录态掉了属于环境问题，不能拿来冒充「这个视频没字幕」。
- 依据全表（`src/content.js:1707–1717`）：truncated 字幕只有一部分 / overflow 字幕比视频还长 / malformed 字幕格式不对 / empty 没拿到字幕内容 / emptyUrl B站 返回了空字幕 / noSubs 这个视频没有字幕 / timeout 字幕检查超时 / rejected 字幕和视频对不上 / ambiguous B站 几次给的字幕都不一样。

### 2. `evalIso` 取错 isolated world ⇒ 三个视频全判「0 块」

- 症状：`FAIL 游戏区 BV1GyZYYNErW 字幕通过闸门（0 块） :: {"verdict":null,"blocks":0}`，影视区、美食区一模一样。
- 真因：调试档 `dist/edge-profile` 里除了我们，还装着**沉浸式翻译**（`amkbmndfnliijdhojkpoglbnaaahippg`）和 **Bili SyncPlay**（`cpgcalajpoihfgfeidmnijcdimnjniam`），它们各自也注入一个 `chrome-extension://` 的 isolated world。旧代码 `x.origin.startsWith('chrome-extension')` **取第一个**，拿到的是沉浸式翻译那个 context，里面当然没有 `__bnState`。
- 现场对照（同一次运行，页面 `BV1w6ZEYrEsb`）：主世界 `#bn-root` 的状态条是「**B站 AI 字幕 · 两次取样一致 · 本地缓存**」，而正确 context（id=5，origin `chrome-extension://mdpphognlfhkeenfmpopbbgmpdhafpfp`）里 `__bnState = {verdict:'stable', blocks:19, notes:1}`。也就是说产品一直好好的，只是脚本在别人的房间里找变量。
- 修法（`test/accept.mjs:86–93`）：`evalIso` 里改成精确匹配 `x.origin === 'chrome-extension://' + extId`，extId 仍是脚本开头从 Edge 配置里按路径查出来的，不硬编码。
- 教训：**验收脚本比产品多一层环境假设**（「调试档里只有我这一个扩展」），一旦调试档里多装一个会注入 isolated world 的扩展，脚本就静默失效——而且表现成「产品功能全挂」，最容易误诊。
- 同一种写法还散在 `test/probe-*.mjs` / `verify-*.mjs` 里（约 15 个文件，如 `probe-notes.mjs:29`、`verify-away.mjs:56`、`probe-vote.mjs:35`），它们只是诊断探针、不参与验收，本轮没逐一改；**用它们查问题前先确认 context 的 origin 是不是我们那个扩展 id**，否则会拿到别人的世界、看到「什么都没发生」。

### 3. 顺手修正 v0.7.4 第 2 节的错误结论（关于后台继续运行开关）

v0.7.4 第 2 节写「『关闭后继续运行后台扩展和应用』在 Edge 157 里已经不存在了，连 `background_mode` 键都不存在」——**这条是错的**，撤掉。2026-11-14 13:00 / 13:10 两次实拍 `edge://settings/system`：

- 该开关**在**「系统和性能 → 系统」里，就在「启动增强」下面第二行，当前**开着**（蓝）；
- 「启动增强」当前**关着**，`Local State` 里 `browser.startup_boost.enabled = false`；窗口全关后仍剩 7 个 msedge 进程，根进程命令行还是 `--no-startup-window /prefetch:5`；
- 截图 `dist/live-settings-system.png`（13:00，216,756 字节）、`dist/live-settings-system-1310.png`（13:10，88,298 字节，由 `PrintWindow(hwnd,hdc,2)` 抓到，浏览器窗口被别的窗口挡住也能抓）。
- 该开关**存在**但它的持久化键仍未定位：`Default\Preferences` 与 `Local State` 里都没有 `background_mode` / `run_in_background` / `continue_running` / `backgroundMode`；`Local State` 只有 `profile.info_cache.Default.background_apps = false`（含义不明，**不要**把它当成这个开关的状态）。
- 当时错在哪：用「Preferences 里搜不到这个键」推断「UI 里没有这个设置」。Chromium 的偏好只在值与默认不同时落盘，键名也可能不叫你以为的那个。**判断某个开关在不在，必须打开 UI 看实时状态并截图。**

另外记一条语义边界：`profile.exit_type = "Crashed"` 是「上次被硬杀」的**历史物证，不会自愈**——只有一次真正干净的退出才会翻回 `Normal`（`exited_cleanly` 在 Preferences 里并不存在）。所以它不能用来判断「现在有没有掉登录」；判断登录态只能让用户看一眼，或者在干净退出后用 `edge-safe.ps1 -Backup` 抓到能读的 Cookies。

### 4. 决策：本轮走 B（不备份，靠纪律），A+（整份快照验证）暂缓

- 用户 2026-11-14 13:0x 拍板：B站「**还登录着**」；断言修正「**授权，改完重跑**」；后台开关「**先别关（推荐）**」。
- 因此本轮**不动用户浏览器**：不关那个后台开关、不关浏览器、不做 Cookies 快照。安全全靠纪律（绝不强杀、只用 `CloseMainWindow()` + 轮询、升级走 `sync-my-edge.ps1` + 手动「重新加载」+ F5）。
- A+ 的前置条件不变：要 `-Backup` 成功，得先让用户关掉那个后台开关 → 关窗口 → 确认进程真退干净 → 再备份。用户不想现在动，就等下一次他主动重登或重启机器时再说。

## 2026-11-16 「接着学」：按课程存进度，点图标就能回去

结论：新增 `src/coursestore.js`（纯函数）+ 弹窗第一块「接着学」。每门打开过的课程在 `chrome.storage.local` 里存一条 `bnc:<课程id>`（课程名、kind、每集 bvid/cid/page/标题/时长、updated_at，不存 URL，跳转时现拼）；弹窗按最近打开倒序列出最多 4 行，每行三行字：课程名 / 已看 X/Y · 总时长 · 懂/半懂/没考 / 继续 第 N 集 · 时间。点一下跳回那一集那一秒，不在视频页也能点。

理由：用户要的是「想打开 B站 学习时一下想到这个插件」。原来只有「当前视频」这一个入口——不在视频页时，点图标只能搜索；看过的课没有落脚点。存一份课程级索引，是把这个插件从「视频页的浮层」变成「学习入口」的最小改动，且不需要服务器。

- **不放 cloud / 不跨设备**。PRIVACY 的承诺是只在本机；换电脑会丢，文档写明。
- **不存 URL**（省地方、也避免域名写死），`episodeUrl()` 现拼 `?p=` 与 `&t=`。
- **不用 IndexedDB**：弹窗在 `chrome-extension://` 源里读不到 bilibili.com 的 IndexedDB，课程索引必须放在 `chrome.storage.local`（与检索索引 `bnidx:`、学习状态 `bnstudy:` 同一处理）。
- **每页面只写一次**：`saveCourseRecord()` 用「课程 id + 集数 + 标题」做签名，刷新/翻页不重复写盘；`updated_at` 由调用时给，用于「最近在看」排序。
