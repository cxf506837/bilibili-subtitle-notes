# B站可核对笔记 · v0.7.3 产品介绍

> 浏览器扩展（Chromium Edge / Chrome，MV3）。最终版本，功能已冻结。

---

## 一句话

**跟着播放头边看边写，每条结论都能点回原句；字幕本身不可信时，它先告诉你，而不是给你一份看着像样的假笔记。**

---

## 它不做"总结"，它做"账本"

市面上的视频总结工具大致同一个流程：丢一个链接进去，吐一坨文字出来。你拿到手之后有两个问题回答不了——**这句话来自哪一秒？**、**这是视频里说的，还是模型编的？**

这个扩展把流程反过来了：

- 它**跟着播放头**走。你看到哪，它记到哪。
- 没看过的段落，它**不写、不剧透**，只画一条虚线占位：`未观看 6:48–57:02 · 88 段`，旁边两个按钮——「总结这段」（花钱补）/「去看这段」（跳过去）。
- 每条笔记由三部分组成：**原话**（逐字引用 + 可点的时间）、**人话解释**、以及它是从哪几句字幕推出来的。

**时间和引文都不由模型手抄。** 模型只负责挑句子（给出 `sentence_ids`），时间由字幕的 `from/to` 算出来，引文由这些句子的原文拼起来。这消灭了两类最常见的假笔记：模型改写一个字就丢弃、模型写个"大概 3 分半"就丢弃。

---

## 三条设计原则

**1. 可核对**
引文只能来自字幕原文。如果模型挑了几句、又自己编了一句"原话"，二者二字片段命中率低于 50%，这条整条丢弃——宁可少一条，不给你一句编的。

**2. 不替你消费**
跳过就是留白。你没看的部分，它不假装看过，也不提前把结论端给你。

**3. 失败要说清**
8 种失败各有自己的标题和「你现在该点哪个按钮」，不共用一个"出错了"：
「这个视频没有字幕」「字幕只有一部分」「字幕比视频还长」「B站 返回了空字幕」「字幕和视频对不上」「B站 几次给的字幕都不一样」「没登录 B站」「清晰度太低，认不出画面字幕」。

---

## 它最硬的一处：B站 的字幕本身是不可信的

这是这个项目里唯一"技术上真有难度"的地方，也是它跟同类工具最实质的差别。

实测（2026-11-13，同一个视频连取 8 次）：**返回了 4 种不同的字幕文件**。正确那份出现 5 次，另外 3 份分别属于一段电动车视频、一段擦桌子视频、和一个 HTML 错误页。还有视频 194 秒、字幕返回 1606 秒的。

所以字幕进笔记之前要过四道闸门：

| 闸门 | 判据 |
|---|---|
| 存在性 | 有中文轨且有 url |
| 时长 | 覆盖比 = 末句时间 / 视频时长，要求 0.85 ~ 1.10 |
| 结构 | ≥8 行、≥120 字、平均句长≥3、累计时长比≤1.15、最大空档≤max(90s, 时长×10%) |
| 稳定 | 最多取样 5 次，**按哈希投票**，同票数≥2 才算 stable，只有一份通过算 single |

票数打平或每次都不一样时**不猜**，判 `ambiguous`，让你点「再试一次」。

代价是多花几秒；收益是**面板上写着的每一句原话，都真的属于这个视频**。

## 用一次是什么体验

以一节 70 分钟的讲课视频为例：

| 时刻 | 发生什么 |
|---|---|
| 打开页面 | 点工具栏图标，面板从右侧浮出，状态条开始跑闸门 |
| 开始播放 | 播放头跨过某一段末尾，才出这一段的一句话 + 人话解释 |
| 你切走 3 分钟 | 回来时顶部一条横幅：「你离开了 3:00 · 这段记了 2 段 [展开补课]」 |
| 讲 PPT 的课 | 画面连续稳住 2.4 秒才截一张帧，本机 OCR，文字挂到最近的笔记上——但**永远不会被当成引文** |
| 看完了 | 「大纲 ▾」看全片一句话索引，可点跳转；「导出」出 Markdown，带 frontmatter、时间戳、可点链接，直接进 Obsidian |
| 下次再打开 | 从 IndexedDB 原样恢复，不重跑闸门、不重复花钱 |

**人话解释的标准是写死的**：先用「它在解决什么问题」开头，别用「它是什么」；能用动词就别把动作变成名词；单句不超过 25 字。提示词里有反例和正例——反例：「讲师深入阐述了协方差矩阵的统计学意义，揭示了变量间的协同变化规律」（拔高、堆名词、等于没说）；正例：「它只回答一个问题：两个东西是不是一起动」。

遇到模型不认识的专名，它必须写「提到了 X，但不确定指什么」，**不许编一个听起来合理的定义**。

## 实测数据（别当成全部跑通了）

**字幕可用率**（60 条真实视频）：ok 14 / overflow 17 / truncated 9 / emptyUrl 9 / noSubs 11。

> 这条要正面看：**60 条里只有 14 条能出笔记**。这是 B站 字幕接口的真实质量，不是扩展的 bug。它选择在剩下 46 条上明确说"不行"，而不是硬编。

- 闸门回归：40 条有字幕样本，40/40 与期望一致。
- 真实字幕样本：2,132 句 / 25,311 字 / 70 分钟 → stable，切成 120 块。
- 真模型（deepseek-flash）6 个连续块：每块 96~184 ms，输入 499~633 token，输出 250~492 token，**23 条要点活下来 22 条**。
- 成本：播到 200 秒、9 条笔记 = 8.2k token ≈ **¥0.012**；补 4 个块 18.7k → 25.0k token ≈ ¥0.006。
- 端到端验收（v0.7.3，4 类视频）：**16/16 通过**。游戏区 120 块 → 117 条笔记 → 导出 79,316 字；影视区 65 块 → 6 条笔记 → 8,354 字；美食区 19 块 → 1 条笔记；无字幕视频判 `rejected` + 「字幕和视频对不上」；切走 95 秒回来横幅正常。
- 单元测试 9 个文件全绿：gate 40 / pipeline 11 / realdata 40 match + 0 mismatch / align 33 / pages 15 / visual 9 / hardsub 61 / vote 10 / section 25。

## 限制（硬前提，不是可选优化）

1. **必须先登录 B站**。未登录时字幕接口返回 0 轨（`need_login_subtitle: true`），这是硬前提。
2. **必须自备一个 OpenAI 兼容的 API**（DeepSeek / 通义 / 智谱 / Moonshot / OpenAI）。Key 只存在浏览器本地，只发给你自己填的那个 Base，不经任何中间服务器。
3. **画面文字要 720p 以上**（截的是解码像素，360p 的中文只有 8~10 像素高，OCR 认不出）。
4. **只做 B站 桌面网页 `bilibili.com/video/`**，含多 P；直播回放和番剧不做。
5. **未上架应用商店**，只能用开发者模式「加载解压缩的扩展」装，浏览器会长期挂一条黄条「此扩展不是来自任何已知来源」，属正常。
6. **它救不了没有字幕的视频**——除非你手动点「用画面字幕试试」，且清晰度 ≥720p。

## 安装（3 步）

1. `edge://extensions`（Chrome 是 `chrome://extensions`）→ 打开右上角「开发人员模式」。
2. 「加载解压缩的扩展」→ 选 `bili-notes/`（有 `manifest.json` 的那一层）。
3. 打开任意 B站 视频页 → 点工具栏图标 → 面板里点「设置」填 API Base / 模型 / Key。

两个安装包：

| 包 | 大小 | 说明 |
|---|---|---|
| `bili-notes-v0.7.3.zip` | 11.6 MB | 完整包，带本地 OCR，画面文字/画面字幕可用 |
| `bili-notes-v0.7.3-lite.zip` | 72 KB | 轻量包，只做字幕笔记，界面上不会出现画面相关按钮 |

## 它不适合谁

- **只想要一段总结贴给别人看的人**——它给的是账本，不是观后感。
- **不想登录 B站、不想配 API Key 的人**——两样都是硬前提。
- **看番剧、看直播回放的人**——不做。
- **想要"一键总结"的人**——它故意不提供：没看过的段落它不写。
