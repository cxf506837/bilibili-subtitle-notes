# 决策记录：视频学习 × bili-notes

> 由 2026-11-14 的 grill（拷打档）产生。每条结论带理由；未定的留在「待定」，定了才动代码。

## 已定

### D1｜第一版目标 = E（「该学什么、学哪部分」的取舍判断）
- 日期：2026-11-14
- 理由：用户在「记背 / 理解 / 取舍」三类需求里明确选了 E（原话「3.先选E」）。
- 2026-11-14 修订：E 的**个性化**版本（「我该不该学、学哪部分」）不做进插件——插件不知道用户的人生目标，硬做只能输出废话。E 只保留可泛化的部分：**这条视频值不值得精看、哪几段值得精看**。

### D2｜纯文本长文产物被排除
- 日期：2026-11-14
- 理由：用户原话「纯文本，一大坨字，就跟看书一样，我可一点都不喜欢看书……你就给个字有啥好看的」。
- 物证：2026-11-14 验收里游戏区视频导出 79,316 字、影视区 8,354 字、美食区 858 字（见 dist/accept-v073b.log）。

### D3｜已有基础设施可复用，不算白做
- 日期：2026-11-14
- 理由：字幕抓取、时间戳、blocks 对齐、字幕/视频错位判定是三种产物的共同底座，16/16 验收验证的正是这层（test/accept.mjs，2026-11-14 通过）。
- 结论：地基保留，产物层作废重做。

### D4｜工具本体从未被使用（事实）
- 日期：2026-11-14
- 事实（用户原话）：没看完过任何一条视频；一直在开发；总结的产物「一点看下去的欲望都没」。

### D5｜判据 = 兴趣；目标 = 让别人也能用
- 日期：2026-11-14
- 用户原话：「如果是这个插件，就是以兴趣为依据，想让大家都能用」。
- 含义：成功判据不再是「笔记准不准」，而是**别人装不装、用了会不会留下来**。硬推论：如果连自己都不用，发布出去不会有人用。

### D6｜形态 = 对话，但要由工具先开口
- 日期：2026-11-14
- 用户原话：「用对话，但感觉不够完善」。
- 判断：对话的短板是「需要用户知道该问什么」，而「不知道该问什么」正是他要解决的问题本身。解法：工具先给出 3 个该弄明白的问题（+ 一句话值不值得精看），用户再接话；想验证某句原话就跳回那一分钟。

### D7｜「记背」判定不成立
- 日期：2026-11-14
- 理由：用户两次未回答「过去一年真正复习过什么」；原话「我可一点都不喜欢看书」。生成卡片而不复习 = 再造一份没人看的东西。

## 待定

- Q12：「想让大家都能用」是否包括发布这堆杂活（打包、上架 Edge 商店、写说明、收反馈）。
- 用户 agent 项目的 CDE 三个卡点，是否用 bili-notes 当练习靶子（S2-4 防崩 / S2-6+8 评测 / S2-5 交付）。

## 硬约束
- 裁决前不动产品代码（含 docs 以外的 src/ 改动）。
- 绝不 Stop-Process -Force msedge；升级只走 sync-my-edge.ps1 + 手动重新加载。
- 需要 Node 20+。文档里的 `node xxx.mjs` 用你自己环境里的 node（本机若没有系统 node，用便携版并把 `bin` 加进 PATH）。
### D8｜只信「真的用一遍」⇒ 产物是任务，不是题目
- 日期：2026-11-14
- 用户原话：「我只会当用户真的用一遍，我从来不信什么改好了和什么破测试，只有真的能用才算好……这是三道题的，也是对整测试部分的唯一答案。」
- 推论：状态机只有两种输入——迷你任务跑通 / 没跑通。选择题（D6 里的「前测」）整体作废。

### D9｜选片前移：先回答「学哪几个」，再回答「看哪几段」
- 日期：2026-11-14
- 用户提出的流程：「用户先搜索，ai推荐，然后ai总结这是啥，并询问你要不要学这个？」
- 采纳：v0.8 主流程改为 选 → 判 → 补 三级；段落级诊断降级。

### D10｜选择题被否决
- 日期：2026-11-14
- 用户原话：「选择题肯定不行」。
### D11｜分开「我自己的需求」与「产品需求」，产品设计冻结
- 日期：2026-11-14
- 用户原话：「我们是不是把开发这个插件和询问用户真实需求弄混了」
- 承认：混了。本轮产出的 spec / 前测打样 / 迷你任务，全部建立在**一个人的口头描述**上，而目标是「让别人也能用」——中间缺了真实的别人。
- 决定：
  1. `docs/spec-v0.8-陪读.md` 冻结，不再迭代，只留档。
  2. 产品需求（B）暂停：没有任何真实用户样本，继续设计等于继续猜。
  3. 先做自用需求（A）：**不写代码**，人工跑一遍完整流程（我当工具、用户当用户），用完记录「哪一步有用 / 哪一步多余」。那才是需求来源。
  4. A 跑通并连续自用之后，才谈 B。
